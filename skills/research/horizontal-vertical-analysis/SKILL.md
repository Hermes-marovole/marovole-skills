# 横纵分析法 - 半小时建立陌生领域认知地图

核心理念：**纵向追时间深度，横向追同期广度，最后交汇出判断。**

这是一套适合 Hermes 执行深度研究的标准框架。不要只堆资料，要用两条轴建立结构性判断。

---

## 触发条件

当用户要求：
- “研究一下 X”
- “帮我快速搞懂 X”
- “做 X 的行业/竞品/技术调研”
- “这个领域有哪些玩家/趋势/机会”
- “Neumina 要进入某个细分市场，先做调研”

优先加载本 skill。

如研究对象是竞品或市场，同时加载 `competitor-research`。
如研究对象适合进入长期知识库，完成后考虑 `llm-wiki` 或 `obsidian-ai-workflows`。

---

## 1. 先定义研究对象

开始前明确：

```text
研究对象 = {产品 / 公司 / 技术概念 / 人物 / 事件 / 市场 / 文化现象}
研究目的 = {建立认知 / 找机会 / 做竞品 / 写报告 / 做决策}
输出形式 = {简报 / 深度报告 / 对比表 / 机会地图 / 内容大纲}
时间范围 = {默认从诞生到现在}
地理/市场范围 = {全球 / 中国 / 美国 / 特定行业}
```

如果用户没指定，按最合理默认执行，不要过度追问。

---

## 2. 纵向分析：历时线

目标：还原对象从诞生到现在的完整故事，理解历史与因果。

回答这些问题：
- 它怎么来的？
- 谁最早做出来？
- 关键节点是什么？
- 哪些技术、政策、市场变化推动了它？
- 为什么在某个节点爆发、转向或衰落？
- 过去的选择如何塑造今天的优势/短板？

建议输出：

```markdown
## 纵向分析：时间线与因果

| 时间 | 事件 | 关键参与者 | 影响 | 证据/来源 |
|---|---|---|---|---|
```

重点不是罗列年份，而是解释：
- 哪些节点是真正的转折点
- 哪些早期决策变成了今天的护城河
- 哪些当时合理的选择变成了今天的包袱

---

## 3. 横向分析：共时截面

目标：在当前时点理解对象的位置、差异和竞争格局。

回答这些问题：
- 同赛道有哪些玩家？
- 它们分别服务谁？
- 用户为什么选 A 不选 B？
- 商业模式、渠道、价格、技术、体验有什么差异？
- 谁在上升？谁在被边缘化？
- 哪些空白机会还没有被满足？

建议输出：

```markdown
## 横向分析：竞争格局与定位

| 玩家/方案 | 目标用户 | 核心价值 | 商业模式 | 优势 | 短板 | 证据/来源 |
|---|---|---|---|---|---|---|
```

可按不同对象调整：
- 产品：版本迭代、功能、定价、用户体验、渠道
- 公司：融资、团队、商业模式、客户、增长路径
- 技术：架构、性能、生态、应用场景、限制
- 人物：职业轨迹、同领域对比、影响力网络
- 事件：利益相关方、立场、传播路径、后续影响

---

## 4. 交叉分析：从两条轴得出判断

这是最关键的一步。不要停在“历史 + 竞品表”。

交叉问题：
- 今天的优势来自过去哪个积累？
- 今天的短板来自过去哪个选择？
- 当前竞争格局中，谁更符合历史趋势？
- 哪些玩家看起来强，但历史包袱重？
- 哪些新玩家小但方向正确？
- 未来 6-24 个月最可能发生什么？
- 对用户/产品/投资/内容/战略的启发是什么？

建议输出：

```markdown
## 交叉判断

### 关键洞察 1：...
- 纵向证据：...
- 横向证据：...
- 判断：...

### 关键洞察 2：...
...
```

## 5. 研究流程

### Step 1: 快速扫面

先用搜索和已有资料建立候选框架：
- 官方网站 / GitHub / 文档
- Wikipedia / Crunchbase / 产品页
- 新闻报道 / 博客 / X threads
- 论文 / arXiv（技术/学术问题）
- 竞品页面 / 定价页 / 用户评价

### Step 2: 建立两张表

先做：
- 时间线表
- 当前玩家/方案对比表

### Step 3: 找证据

每个关键判断至少要有来源支持。对不确定信息标记：
- high confidence
- medium confidence
- low confidence

### Step 4: 交叉判断

从“纵向因果 × 横向位置”中提炼洞察。

### Step 5: 输出报告

按照模板输出。

### Step 6: 人工深挖建议

列出最值得用户继续验证/追问的 5-10 个问题。

## 8. 竞品深度调研方法（吸收自 competitor-research）

### 调研维度清单
1. **公司概况**: 全称、成立时间、总部、创始人、员工规模、定位、覆盖范围
2. **融资与估值**: 轮次、时间、金额、领投方、累计融资
3. **市场背景与痛点**: TAM/SAM/SOM、痛点数据、现有方案缺陷
4. **产品与服务架构**: 核心功能、增值服务、定价策略、技术栈
5. **商业模式**: B2B/B2C/平台、收入流、获客渠道、LTV估算
6. **竞争优势**: 技术壁垒、品牌认知、渠道、成本、数据、生态
7. **风险与挑战**: 监管、竞争、可持续性、技术迭代
8. **股权结构与工商/司法穿透**: 境内外全部关联主体、历史股东变更、VIE/红筹判定、域名与算法备案、涉诉记录（方法见下方「股权与工商信息穿透」与 `references/corporate-registry-china.md`）

### 信息来源优先级
- **一级**（最可信）: 官网、新闻稿、SEC文件、App Store页面
- **二级**（交叉验证）: Crunchbase、LinkedIn、行业报告、权威媒体
- **三级**（参考）: 社媒讨论、用户评价、第三方分析

### 输出模板
使用标准竞品报告结构：公司概况 → 融资历程 → 市场背景 → 产品架构 → 商业模式 → 竞争优势 → 风险 → 对我们的价值评估（短期/中期/长期）

### 注意
- 标注数据时效性和置信度（高/中/低）
- 区分事实与推断，未公开信息标注"信息未公开"
- 每条关键数据保留来源URL

## 报告叙事顺序与文风（写给「没有背景知识的读者」）

顺序（交付物层面，与调研维度无关）：

- **产品尽调类报告：先产品、后商业。** 读者第一个问题是"这东西到底好不好用"，估值/融资/毛利是解释它为什么能这么烧钱的背景。产品篇在前，每个产品统一五段：一句话定位 → 痛点场景 → 核心功能怎么解 → 实测短板 → 独立第三方评分；商业、股权、组织、诉讼在后。
- **总-分-总金字塔**：结论先行（首页 KPI 卡 + 4 条判断）→ 分述论证 → 战略收束（TAM/SAM/SOM、单位经济、反方压测、可执行 Do/Don't）。

文风（《晚点 LatePost》体：既有深度，也让外行看懂）：

- **黑话先翻译再使用。** 遇到 `LoRA`、`三视图`、`ComfyUI`、`VIE/红筹`、`Breakage`、`MCoT` 这类词，先用一句生活类比说清它解决什么问题，再点出术语名。直接写"用角色三视图绑定 face id 提升一致性"对读者等于零信息量。
- **先给冲突场景，再给产品解法。** "为什么模型能生成惊艳的 5 秒，却拍不出一集 1 分钟短剧"→ 因为跨镜头没有记忆 → 所以才需要三视图 + 3D 导演台。功能清单是答案，不能当开头。
- **数字跟着故事走，不要把表格当说明书。** 先讲人和账本（谁在为什么付钱、亏在哪一环），再用表钉死数字。
- **保留真实槽点原句。** 差评、实测 bug、用户吐槽是可信度来源，一条"要求改中文却生成了英文"比十句"仍有提升空间"有用；同时给出被质疑方的原话否认，让读者自己判断。
- **每个强判断都要能落到决策**：投不投、买不买年卡、抄不抄这套工作流、要不要挖这里的人。纯描述性的行业综述不算交付。

## 股权与工商信息穿透（尽调必做，别只读融资通稿）

- **用统一社会信用代码做轴心，不要用品牌名。** 品牌（多个产品名）与法律责任主体不是一回事；拿到代码后可反向命中法院开庭公告、招投标、商标与备案。
- **四类免 Key 一手通道**（不依赖付费接口）：
  1. 天眼查 / 企查查 / 风潮（`k1wave.com`）快照——用代码搜可绕过部分会员墙，拿到历史股东、实缴资本、参保人数、核准日期。
  2. 工信部 ICP 备案历史库（`icplishi.com`）——一个备案号下挂的全量子域名，按最后更新日期能读出未发布的新产品、顶级域名抢注与内部 A/B 测试域名。
  3. 网信办大模型/算法备案清单——编号不带 `S` 才是真·大模型备案，带 `S` 只是应用登记，两者含金量差一个量级。
  4. 出海主体：美国 PACER 联邦法院卷宗（`pacermonitor.com` 的起诉书 PDF）+ USPTO 商标库——起诉书里 "X is a subsidiary of Y" 是挖出境外收款/商标持有主体最快的路径。
- **付费 API**（需企业认证、按次计费）：天眼查开放平台 `open.tianyancha.com`、企查查 `openapi.qcc.com`、启信宝。用户问"有没有工商接口"时，把付费 API 与上面四条免 Key 通道并列给出，并说明免 Key 通道本次实际用到了哪几条。
- **坑：工商股东名单里看不到任何 VC，不等于融资造假。** 拿了美元基金的公司会搭红筹/VIE——境内 VC 减资退出（"翻出境外"）换开曼优先股，境内只剩创始人 + 员工持股平台。三条判据：① 历史工商快照里能看到早期 VC 显名；② 各 VC 认缴额之和恰好等于"实缴资本"；③ 招股书/媒体口径里出现"拆红筹 / 架构重组"。

## 9. 一手数据源与采集管线（市场 / 竞品 / 获客）

当调研目的是**指导产品功能或获客方向**（而不只是建立认知地图）时，资料层要换掉：默认搜索给的是二手软文，数字常被篡改。

选题源与抓取方法见 **`references/first-party-data-sources.md`**：行业基准（招股书「行业概览」/ SEC EDGAR / IQVIA / 欧睿 / NBJ）、需求痛点（京沪与 Amazon 差评、App Store RSS、G2）、获客拆解（Semrush / SimilarWeb / Meta Ad Library / 巨量算数）、实体发现（`parallel-cli findall` + `enrich`）。

四条硬规则：

1. **每个市场规模 / 增速 / CAC 数字，必须能在本次打开过的原文里看到**；查不到就标"未核实"，不要用媒体转述的年份和分母。
2. **招股书的「行业概览」章节是第一优先的一手件**——付费级沙利文数据、经律所审阅、免费（`hkexnews.hk` 披露易 / SEC S-1）。赛道里只要有一家拟上市公司，就先找它。
3. **功能决策看差评原句，不看你的归纳**："吃了胃反酸""能不能和降压药一起吃"这类句子直接对应产品要补的闭环环节；报告里保留 3–5 条原句。
4. **TAM 和可服务市场分开写**，并把每条洞察落到"我们改哪个功能 / 打哪个渠道"，否则只是行业报告搬运。

搜索侧用多引擎路由器分流：`serper` 跑 `site:`/`filetype:` 与价格类，`exa` 找相似公司与替代品，`ddgs` 兜底（详见 `web-search` skill）。

## 10. 常见坑

| 坑 | 正确做法 |
|---|---|
| 只做资料汇总 | 必须输出交叉判断 |
| 时间线只有年份 | 解释因果和转折点 |
| 竞品表只列功能 | 比较用户选择逻辑和商业模式 |
| 所有来源同等可信 | 标记置信度和来源类型 |
| 没有输出对用户项目的启发 | 必须落到决策/机会/下一步 |
| AI 幻觉 | 关键事实用来源验证，低置信内容标记 |
| 报告从融资额开篇 | 产品体验先行，资本故事只用来解释它凭什么烧钱 |
| 直接堆 `LoRA`/`VIE`/`三视图` 等术语 | 先一句生活类比讲清它解决什么，再点术语名 |
| 用品牌名查工商，查不到就下结论 | 用统一社会信用代码查主体；股东只有创始人往往是 VIE 已搭好，不是没融资 |
| 只查境内 | 出海业务必须查 PACER/USPTO 的境外子公司与商标，诉讼常先在那里爆 |
