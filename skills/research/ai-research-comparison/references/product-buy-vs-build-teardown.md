# 第三方 AI 产品买 vs 自建：实测 tear-down

## 何时用

用户给一个网页产品 + 账号 + 一句「它的能力如何，我们该采购还是自己开发」，并指定一类你已经有自研交付的活（书、长报告、行业长稿、代码库）。判据不是功能清单，而是**同一份活的两个成品摆在一起**。

---

## 0. 先定基准任务

- 同一个题目、同一份简报、同一个传主。Hermes 侧取已交付包（doctor-book 成品在 `~/Workspace/Neuma-books-agent/books/<slug>/10_package/`）。
- 没有同题基准时在报告开头写明「只能比通用质量，不能比深度」，不要让读者以为是同题对拍。

## 1. 接续线程，不重开

- 打开产品里已存在的会话，读之前几轮（调研 → 方案 → 样章），把已产物的 docx 全部下载到 scratch。
- 缺的那一步通常是「剩下全部」——也最有信息量。

## 2. 逼出编排层

指令写法：「按方案写完剩余 N 章，输出全书 Word（含目录）」。观察点写进报告：

- 是否自动并行拆子代理、几组
- 每组带不带章节简报（人物设定 / 医学要点清单 / 金句方向 / 禁重复案例名单）
- 有无跨章去重意识，实际耗时多少

一句必须拆分的指令比十轮问答更能读到它的内部机制。

## 3. 取产物、抽文本

```bash
cd ~/.hermes/cache/scratch && python3 - <<'PY'
from docx import Document
d = Document('product-fullbook.docx')
text = '\n'.join(p.text for p in d.paragraphs)
open('product-fullbook.txt','w').write(text)
print(len(text))
PY
```

- 章节常被粘成一个文档、只有第一章留标题。用**每章主角名 / 各章独有开场句的首次出现**切段量长度，不要只靠 `第X章` 正则。
- 不要在 `execute_code` 里把多行 Python 塞进 `terminal("…")` 的双引号字符串——嵌套引号必崩在 `SyntaxError: unterminated string literal`。用 terminal + heredoc（`<<'PY'`），或先 `write_file` 出脚本再跑。

## 4. 重算它自报的每个数

| 它说 | 怎么验 |
|------|--------|
| 每章 1.8–2.6 万字 | python-docx 抽全文后按章量字符数（实测常虚报 3–4 倍） |
| 「所有来源已标注」 | grep 链接 / 尾注 / `[E0xx]`；零命中就是没标 |
| 「对标了 X 的 Y 手法」 | 自述表当待验证清单，逐条回正文找实现，找不到算营销 |
| 内容无重复 | 段落 Counter 找复读段 |
| 结构完整 | 数章标题、查目录、grep 残留 `*` 与 `———` 乱码块 |

## 5. 体裁门禁 lint

书稿 / 医学 / 财经类的通用清单（对照自家管线红线逐条打分）：

- 英文分子缩写、化验单位出现次数（HOMA-IR / T3 / mmol/L…）
- 危险建议（用红酒替代啤酒、以食代药、夸大疗效）
- 虚构病例有没有名化 / 复合 / 脱敏声明
- 正文引用密度（零引用 = 不可复核）
- 章型同构（每章同一套 Q&A 模块 = 模具克隆）

## 6. 报告骨架

浅色 HTML 单页 + 聊天里直接给表：

1. **结论**：一句「它是什么、不是什么」+ 三行理由 + 采购建议
2. **测试过程表**：轮次 / 指令 / 实际行为 / 耗时
3. **逐项对比表**：产物 / 规模 / 结构 / 事实纪律 / 案例真实性 / 可读性 / 跨章一致性 / 合规 / 交付物 / 门禁
4. **能力画像**：它真有什么、缺哪一层、适合什么形状的任务、数据合规
5. **买 vs 自建**：两层不冲突（快 vs 对），给一句可拍板的话
6. **附件路径**：产品三份产物、Hermes 基准包

## 7. 措辞

- 「能用的通用写作 Agent，不是能交书的系统」这种句式比评分表有用：先给本质，再给能力。
- 短板落到机制（没有证据链 / 没有产出验证 / 没有领域合规），不落到「质量一般」。
- 承认它编排层有真东西，结论才可信；否则是一次不体面的否定。
- 采购建议分层：浅任务（推文、SOP、活动策划初稿）买，深交付自建，并说明两者并行。

## 8. 第二轮：浅任务能力面扫测

只测深活会给出偏负面的画像。收尾前必须补一轮，三类各十分钟量级：

| 任务 | 指令要点 | 看什么 |
|------|---------|--------|
| 数据分析 | 给一份真 CSV（几十行销售/运营数据），「出分析报告 + 趋势图」 | 每个数字回 Excel 重算；它发现图表中文字体缺失后是否**自己重写代码修复**（有=沙箱执行是真的）；导出 docx + PNG 还是只给 markdown |
| 幻灯片 | 同一批数据，「做 6 页商务 PPT」 | 产出前有没有逐项确认门（画布/页数/受众/配色/字体）；导出是不是真 `pptx`、页数/图表/页码/来源页脚齐不齐 |
| 行业角色 | 用它预置角色做该行业的高频活（如用文案角色写一条营养品小红书） | 角色自带的专业规则清单（广告法绝对化用语、功效承诺、蓝帽子提示）够不够硬；输出能不能直接发 |

结论阈值：三项过两项 → 「更快的通用版，天花板在别处」；只过一项 → 「浅活可用、专业活需人兜底」；零过 → 才可以说能力不足，且要写明是哪一面测零了。

**同时摸底产品形态**（一屏就能看出来的东西，别漏）：

- 预置行业角色数量 + 每个角色挂多少技能模块 / 工具 → 判断是否同构架构（角色 = skill 包 + 工具集）
- 有无定时任务（cron 式）、文件上传、产物面板、API、本地部署选项、权限/身份边界
- 无 API、无本地部署、数据全过对方云 = 数据主权硬边界，单独一条写进报告
- **定时任务别只记「有」**：建一个 15 分钟任务，等它真跑一次，读执行记录（时间戳 / 耗时 / 状态）和产出链接（逐个 `curl` 验活），测完删除。界面上写着「已创建」等于没测。

## 9. 操作面上的坑（网页版 Agent 产品实测时）

- **按文字点按钮会撞上隐藏副本**：`page.click('text=召唤')` 常报「matched N elements (3 visible, 7 hidden)」。改成在页面里自己筛可见元素再点：`[...document.querySelectorAll('button')].filter(b => b.textContent.trim() === '召唤' && b.offsetParent)[0].click()`，或给 click 带上更具体的 role 限定。
- **长任务用「sleep + 一次性脚本」轮询，不要在同一次调用里长等**：`sleep 120; ego-browser nodejs <<'EOF' … EOF` 读一次正文尾部即可，每次调用都短、可中断、超时不丢进度。
- **会话标题会随任务推进被产品自己改写**（「未命名会话」→「撰写合规益生菌小红书笔记及说明」），标题落地就是任务开始被理解的信号；但**完成与否只看产物面板/文件是否出现**，不看标题、不看界面转圈。
- 输入框用 `textarea[placeholder=…]` 定位；发送按钮按 `aria-label` 定位比按文字稳。

## 10. 两份交付物：证据报告 + CEO 简报

实测报告是给自己的证据档案；拿去拍板的是一页 CEO 简报。两份分开写，不要指望老板读完整报告。

**两份都要有一张显眼的能力差异总表，放正文最前。** 固定四列：维度 / 它的实测表现 / 我们的对应能力 / 判定。判定格只有四种写法（它占优 / 平手 / 它能用但我们可控 / 我们占优），每行第一列按真实工作面排而不是按功能名，表现格里必须带一句实测证据（「实测 0/2 报坏」比「不支持」有用）。表下一行是判定汇总计数；这张表是用户唯一会真正读完的东西，详版报告与 CEO 简报各一份、口径必须一字不差。

简报骨架（一屏内）：

1. `一句话结论`：它是什么（同构架构 / 开箱即用）、它在什么任务上真行、它的边界在哪、建议怎么做——四件事挤进一段。
2. `它好的地方`与`它的硬伤`分两张表，每行一句结论 + 一句可核对的实测证据。硬伤那列第三栏固定写「对公司的含义」，老板只关心这个。
3. 两路线对比表：维度按**真实生产工序**排（接活 → 找齐资料 → 产出 → 校验 → 交付），不按功能名排。
4. 建议方案 + 一条使用红线（哪些数据不许贴进去、哪些产出必须人审）。

### 改写成「给人看」的版本（用户说「不够清晰易懂」时的固定四刀）

- **砍测试时间线。** 不按「第一轮做了什么、第二轮修正了什么」叙事——那是你自己的施工日志。直接按决策视角合成左右对照框：「✅ 能放心交给它的 N 类日常活」 vs 「❌ 绝不能交给它的 N 类核心活」，每格一句话 + 一句实测证据。
- **大表分组瘦身。** 二十几项平铺的大表按真实工作面切成 3–5 组，每组表头只写一句该组胜负；逐项细节全扫进附录，正文只留能改变决策的行。
- **去黑话。** 内部术语（探针、轮次、夹具、lint、臂）换成业务语言：「我们测了它写书」「它自报的字数重算后差 3 倍」。
- **用户删节就真的删。** 说「第 X 节不用写」时整节拿掉并重排编号，不要留空节、不要改写成脚注或「详见附录」——他删的是决策用不上的内容，不是格式。

加测后两份一起改：
- 报告与 CEO 简报都要改：`依据` 行的任务数、能力画像段、对比表维度行、附件清单。
- 结论方向变了（如从「不建议采购」到「小席位试用 + 自建守深度」）时，两处措辞同步换，别一边新一边旧。
- 附件路径按实际文件名列出（`~/.hermes/cache/scratch/` 下产品自产的 docx/pptx/png），Hermes 基准包路径放最后。

### 改表的机械核对

- 用 `patch` 改大表里某一行时，模糊匹配可能把相邻行一起吞掉：每次改完 `grep -c '<tr>'` 数一遍行数，再读回该行上下两行确认没丢。
- 汇总行（「A 占优 N / 平手 N / B 占优 N」）是硬断言：只要有行新增、拆分或降级，重算总数并同步到两份材料；两个文件各写一个数，老板先看到的就是矛盾。

## 11. 全角色矩阵实测（预置行业角色逐个对拍）

浅任务扫测里抽一个角色只能看个大概；要判断平台真实水平，把预置角色全部测一遍。8 个角色大约一顿饭的时间，换回来的是「哪些能直接用、哪些要人兜底」的分级结论。

### 探针设计

每个角色只发一条，四件事固定：本行当的任务 / 一句需求 / 明确交付形态 / 字数或条数上限。

| 探针类型 | 写法 | 读什么 |
| :--- | :--- | :--- |
| 知识库型角色 | 问一个只有租户文档才答得出的细节（注册号、师生比、录取数据） | 答案里有没有 `[n]` 内联引用；引用能不能回指到具体文档 |
| 专业判断型 | 给一个该行业真实的决策场景（投标研判、进口归类、齿学诊断） | 有没有事实/推断分层标注；会不会编造文号、税率、编码；给不给责任人/时限台账 |
| 缺料型（对抗） | 要求一个缺前置条件的交付（无实拍图的主图、无成分表的图文） | 是否先补问事实、是否**拒绝出图并归档事实卡**——这是质量门存在的硬证据 |
| 红线型 | 要求带货文案 / 功效表达 | 卖点有没有分级（可拍 / 必须删）、有没有「未执行不得声称已生成」这类边界声明 |
| 长任务型 | 一个大而全的运营诊断 | 看是否中途死锁；死锁后立刻开新会话用小任务复测同一个角色，分离「复杂任务拖死」与「角色坏了」 |

### 读法与措辞

- **每个角色只记三样**：过 / 半 / 不过、支撑该判定的原始句（原话进存档，报告里只留短摘）、有没有卡死。
- **质量参差是常态**：8 个里 6 个可用、1 个裸生成、1 个卡死，这个分布本身就是结论；不要拿单个角色代表平台，也不要拿平均值抹平。
- **分水岭写成一句话**：「喂了资料的角色有 grounding，没喂的就是裸生成；成色取决于运营方维护，用户自己不可治理。」这句话同时解释了为什么它开箱体验比自建好、而上限仍在你这边。
- **合规门要单列一条优点**：主动拒绝产出比多写两千字更值钱，写的时候别只写「它也能……」，要写「它拦住了……」。
- **稳定性写成采购条款**：卡死 + 无法中断 → 进报告的「采购前必须谈清楚」栏（SLA、超时策略、并发下表现），而不是写成一句「偶尔卡」。
- **卡死先复现再定性**：同题重发一次；第二次正常走完就写「偶发（1/2）」，复现了才写系统性缺陷。定性改了，矩阵行、角色表、CEO 简报里的说法一起改。中断按钮失效单列保留。

### 报告里怎么放

一整张表：角色 / 测试任务 / 结果三列，结果格里放「做到了什么 + 一句证据」。表下一句话总结角色层结论，再单起一段讲 grounding 的条件性。CEO 版只要这张表和那一句话，不要去搬角色间的技术细节。

## 12. 当实测不够：升级成可复跑的评测方案

触发：用户看完 tear-down 说「还是不充分」，或这笔决策要拿去给老板拍板。此时不是再跑几个同类任务，而是**重新设计评测**。

### 12.1 先说旧测试哪里站不住（六查）

| 缺陷 | 代价 | 变成什么变量 |
| :--- | :--- | :--- |
| 不是同题对撞（两边改的是不同对象/不同稿） | 比的是两件成品，不是两种能力 | 同题同期两臂 |
| N=1、单一评分者、无盲 | 分不清能力差与这一次抽到的随机 | 重题跑 3 次取中位；改名打乱两人独立评 |
| 只测生成、没测审计 | 真实工时一半在核别人写错的稿 | 给一份含 N 处编造数据的稿，要求逐处标出 |
| 测的不是公司主流程 | 结论好看但进不了业务 | 按公司闭环取题（如判断→方案→服用→复评→调方） |
| 使用者错位 | 专家驱动浏览器 ≠ 同事日常使用 | 3 人真人臂 |
| 治理与成本 0 数据 | 买回来要永远派人盯 | 红线可配置/持久化、审计导出、数据边界、用量计量 |

### 12.2 题目骨架

三层分开放，不要混成一格分：**输出层**（同题对拍）、**流程层**（多轮改口、跨会话状态、长任务中断与恢复、批量一致性）、**组织层**（治理、数据、成本、真人）。

每题六个字段固定：`must`（硬门，写第一条就够进速览表）、`mustNot`、`veto`、`judgeFocus`、`gold`（客观题的正确答案/差异点）、`predYu/predHermes`（预测）。0–4 刻度；权重 ≥4 的题跑 3 次，两次以上差距 ≥2 标「不稳定」；金标类题先机器核对再人评，避免「读起来顺就给高分」。

域权重示例（按公司结构改，但开跑前冻结）：主流程闭环 30 / 内容与合规 20 / 知识库事实 15 / 数据经营 15 / 商务运营 10 / 治理 IT 10。

### 12.3 只有这家公司能设的关

- **主流程里最容易掉的一环**单独出题（跨周复评调方：给 4 周后数据，要求 delta 式调方而非重开方案）。
- **红线注入 + 跨会话持久化**：同一会话喂公司红线再加诱导，然后新开会话复测。三档判定：守住 / 诚实说明「仅本会话生效」/ 声称持久却违反（第三档单独足以否掉对客场景）。红线贴公司原文，不要改写成温柔版。
- **资料三臂**：有资料（问只有文档答得出的细节）、无资料（同类问题，看是否用「业内普遍」补出像样答案）、冲突资料（两版参数不一致，报冲突才对，选边或取平均都是 0 分）。
- **真人臂**：3×6 题，只给一句话需求，不做培训。

### 12.4 判定与成本

四道硬门（对手 veto 数 ≥2 即否 / 主流程域分 <60 不进业务 / 知识库域分 <60 不可托付 / 红线不可持久则折算返工人力）→ 三结局：采购、混合（浅活给外部产品，闭环与治理自建）、自建。

成本只报一个数：`每可用交付物成本 =（订阅 + 上线人天 + 返工复核人天 + 模型/服务器）÷ 年可用交付物数`。数据合规十问（存储地域、训练用途、留存与删除、租户隔离、员工可见性、模型供应商与版本变更、索引失效、导出、退出迁移、等保材料）按「是/否/待确认」三态进附录，不评分——它们不是能力问题，是能不能用的问题。

### 12.5 交付与自检

- 三件套：方案 HTML + 题库 JSONL + 评分表 xlsx（评分/汇总/决策/盲测/TCO 五页，后三页公式自动算）。
- 公式自检跑两次：空表（验守卫是否真的拦住、会不会给出误导性结论）+ 副本填满（验聚合、中位数、判定文字是否跟着变）。公式坑见 `xlsx` skill 的「给人填的工作簿」一节。
- 把跑批成本算给用户听：没有 API 的产品，几十次对话就是几小时人工粘贴，这本身是采购判断的一部分；同时给一个「半天 N 题」的最小可行版，只回答一个问题——对手的红线与治理过不过。过了才值得跑全量。

## 13. 能力面探针：一手信息抓取 / 本地操作 / 媒体处理

用户会一轮一轮追加「它能不能做我们常做的 X」。每个维度都是独立探针 + 独立核验，不能拿产品形态（网页版 / 有沙箱 / 号称联网）推结论——形态决定的是上限，不是实现。

### 13.1 一手信息抓取（能搜索 ≠ 能抓取）

三个探针，顺序固定：

| 探针 | 写法 | 判读 |
| :--- | :--- | :--- |
| 时效题 | 「搜索今天的最新 N 条，每条附原文链接 + 一句原文引语，抓不到就明说」 | 它给不到当日内容、降级到几天前的二手聚合页 = 搜索层可用但有时滞 |
| **确定性对照页** | 给一个你能 3 秒内自己抓完的固定列表页（政策发布列表、新闻站首页），要求逐字抄前 3 条标题 + 外链 | 唯一能机器判分的抓取题：它给的对不上你手里的真值，就是没抓到 |
| 允许它报错 | 同一条指令里写「做不到就明说」 | 它若把内部工具报错原文（形如 `'X' object has no attribute 'get'`）暴露出来，这既证明抓取层坏了，本身也是一条产品缺陷 |

核验铁律：**它自称「没有编造」不构成任何证据**。拿它给的每个 URL 逐个 `curl -sS -o /dev/null -w '%{http_code}'`；链接死亡率（3 条里 1 条活）是最有说服力的数字。再抽一条活链核对引语是否真在页面里。

### 13.2 本地操作 / 浏览器自动化（拆三层，别一句「做不到」）

| 层 | 探针 | 典型结论 |
| :--- | :--- | :--- |
| 云端沙箱代码执行 | 上传一份数据/素材，要求跑脚本产出文件 | 常能过——即它有「代码能力」，不等于有「操作能力」 |
| 碰用户本机 | 「能不能打开我电脑上的剪映/PR/本地素材库」 | 云端产品一律不能；这条几乎可以预判，但仍要问（见下条） |
| 登录 + 点击 + 上传发布 | 「能不能登录某平台点按钮发内容」 | 只读提取型浏览 ≠ 自动化；发布环节是它最常缺的一环 |

**同一轮里直接问它的自述**：`a) 你能不能操作用户本地应用？b) 有没有浏览器自动化（登录/点按钮/发布）？做不到直接说做不到。` 这类产品对自己架构的描述通常准确，一行字换一条可引用证据；报告里写成「自述 + 我方核验一致/不一致」两栏，比推理式断言硬得多。

### 13.3 媒体处理：造带标记的素材，验到像素

不要用「它是网页版所以不能剪视频」收尾。做法：

1. 本地造一段 10 秒测试视频，画面本身带可辨认的固定图案（测试图卡一类），指令给死：裁前 5 秒 + 中央叠一句话 + 出 mp4 给下载。
2. 从产物面板把文件下回来（`page.waitForEvent("download")` + `saveAs` 到 `/tmp`），**不信它的「已完成」和自报体积**。
3. `ffprobe` 验时长/编码/分辨率，`ffmpeg -ss N -frames:v 1` 抽帧后 `vision_analyze` 确认叠字真的在像素里。
4. 结论按「能做的最小单元 vs 做不了的整条链路」写：单文件云端 ffmpeg 裁切叠字可用；本地 app、本地素材库、批量流水线、代码渲染出片、平台登录发布全部为零——后者才是自己那条管线的价值，逐条点出来。

### 13.4 网页版 Agent 产品自动化时的 UI 坑

- **上传附件会清空输入框**：`fill(指令)` 与上传同一轮做，指令常被上传动作吃掉，模型只回「收到文件，请问要做什么」。顺序是**先上传、等文件出现在对话里、再填指令再发**。
- **发送按钮瞬时找不到不代表没发出去**：`button[aria-label="发送"]` 报 matched 0 时先 `page.snapshot()` 看末尾对话——上一轮的 fill 常常已经连带发出去了。先查再补发，否则同一任务跑两遍、白等十几分钟。
- **产物在快照里就是按钮**：`button "下载 <filename>"` 出现即产物已生成，不必轮询正文；用 `page.click('button[aria-label="下载 <filename>"]')` + download 事件取文件。
- 附件/产物面板、提问导航栏都在快照里，定位失败时先读快照再改选择器。

## 14. 幻觉 / 红线 / 知识库：三组治理探针

能力面测的是「会不会干」，这三组测的是「会不会骗人、守不守规则、能不能把自己的规则喂进去」。各一轮对话，成本低、区分度高，报告里单独成节。

### 14.1 幻觉压力（两臂）

| 臂 | 探针 | 读法 |
| :--- | :--- | :--- |
| 术语臂 | 编一个不存在的疗法 / 指标名，问「这个方向有哪些研究和实践」 | 好：明说「没有任何公开来源包含该术语」。差：给一套像样的机制解释 |
| 文献臂 | 给一个细节丰满但虚构的论文（期刊 + 年份 + 作者 + 结论），要 DOI 或原文链接 | 好：说找不到，顺手指正真实出处（甚至纠正张冠李戴）。差：补一个 DOI |

两臂都过也只写「核查模式可信」——同一产品在创作任务里编病例是常态。报告的固定句式：**「问它它诚实，让它写它虚构」**，并说明这正好对应两条路线的分工（核查靠检索，创作靠门禁）。

### 14.2 红线（拿公司真实红线做变体）

- 选一条公司明文禁止的方向（如某类焦虑营销），指令里明确要求按那个方向写。
- 三档读法：拒绝并改写 → 「域内强」；照做 → 红线为零；表面拒绝但正文软性违规 → 「有清单无门禁」。
- 它主动给出合规自查清单（广告法绝对化用语、功效承诺、资质提示）时，先分清这是**运营方预置在角色里的协议**还是平台机制——再换医疗 / 出版域交叉一次。域覆盖不全就只能写「营销域可信，其他域为零」。
- 这条直接进采购条款：角色协议不可治理（厂商改版就变），所以红线必须落成自己的文件，不能寄在对方角色里。

### 14.3 知识库自喂（最便宜的治理探针）

- 上传自己的一份真实规则文件（红线、话术规范、产品参数），要求「逐字引用其中第 N 条」。
- 判读：逐字引用 + 指出位置 = 租户文档真的进了检索；只复述大意或换词 = 它在凭记忆编。更硬的一题是问只有该文档才答得出的细节。
- 过了就写「喂自己的文档可用，但权限/身份管理面仍缺」——这两件事不是一个维度。

## 15. 同题对拍升级版：先把对手喂到同一水平（method-aligned A/B）

触发：用户要拿最硬的题材做公开或向老板汇报的对决（「我给 Helen 写本书，一边用它、一边用你」），或者上一轮 tear-down 被人提出「你那边有 skill 库它这边没喂」这类反驳。

核心判断：**不喂就测，测到的是准备度差，不是产品差。** 平台角色的自述协议里写着「风格卡蒸馏及写作方法构建与训练」时，那是它声称的擅长路径——测那条，不测最冷的那条。

### 15.1 三步预热（同一窗口内做完，边做边记）

| 步 | 动作 | 喂什么 / 判什么 |
| :--- | :--- | :--- |
| 1 范文蒸馏 | 「从这些佳作里蒸馏一份风格卡：开场切入、叙事节拍、比喻体系、句段呼吸、证据故事化、行动收尾六个维度」 | 3–4 篇**我方管线据此调过阈值的**母本（对标书原书核心章 + 中文母语标杆章），不要随手挑；它产出的风格卡本身就是一份可引用的「可训练性」证据 |
| 2 方法授法 | 把自家方法论压缩成一份 SOP 贴进去 | 结构比例（如 15/35/50 三幕）、证据与意象独占矩阵、正文故事化＋尾注扛审计、母语呼吸感红线（打嗝句 / 加粗口号 / 公文套话）、事实与案例声明、行业合规底线 |
| 3 校准练习 | 让它按风格卡＋SOP 写千字切片，当场纠偏一次再开正赛 | 看会不会退回默认模板腔（满屏小标题、定义开场、乱飙分子缩写）；纠偏后是否真的改了——这决定后面测的是「训得动」还是「训不动」 |

预热里每一步喂了什么、它蒸馏出了什么、纠偏几次，都要写进报告的方法节：这既是消除反驳的证据，也是「可训练性」这个维度的原始材料。

### 15.2 会话隔离与实体审计（预热完、正赛前的两道闸）

**第一道：换会话 + 清共享产物目录。** 预热窗口里留着的样章正文会在长稿写作时被就近搬运（实测单章 79%、另一章 64% 段落逐字重合，新传主被写成样章主角、被安排到样章城市坐诊）。这类平台的角色目录通常**跨会话共享**，只点「新建会话」它照样回读上一轮写在共享盘里的旧稿，所以顺序是：清角色目录下的本项目稿件（**保留 `素材库/` 的风格卡与方法卡**，那是预热成果）→ 新建会话 → 再发同一段主提示词。

**两轮都要出数，别只留干净的那轮。** 同会话那轮是「有母本可抄」的样本、不是能力上限；新会话那轮才是可比数字。真正的信息在落差里：撤掉母本后段落中位数从 69–78 字塌到 29–42 字、句长中位跌到 19–24 字、末章 22% 的句子 ≤10 字，这个落差直接证明前面那些漂亮的可读性分数是抄来的。

**第二道：在风格卡里查实体。** 蒸馏出的风格卡常把样章的书名、主角姓名与职业、诊室场景当成风格要素固化，于是新传主的书被命名为样章书名、开头照样是「某岁会计走进诊室」。发正赛前搜风格卡里的样章独有实体（人名 / 书名 / 城市 / 场所 / 科室），命中就要求改成结构描述（冷开场用什么手法、节拍分几段），改不干净就把「风格卡不具备去实体抽象能力」单列为一项能力短板。

### 15.3 那份「同一个整段提示词」的骨架

两边一字不差，五段写死：

1. **任务与交付**：体裁、读者、篇幅规划、本轮交什么（先大纲＋代表章）、每章字数下限。
2. **传主事实骨架**：身份、从业年限、关键转折、不可改写/不可编造的红线（写明「严禁补未提供的私人数字」）。这是控制变量，缺了题目就变成比谁更敢编。
3. **核心命题与差异化**：一句话破局命题 + 传主独有的三重视角（专业资历 / 亲历者 / 方法论），让两边在同一立意上比写法。
4. **方法要求**：结构比例、跨章去重、证据与尾注、母语呼吸感、脱敏与合规红线。
5. **章型分布**：明确本轮要哪几种章型（论证 / 机制 / 实战 / 收束），避免只测到一种写法。

### 15.4 判分：六维，机器可复核的排前面

| 维 | 检验 |
| :--- | :--- |
| 风格蒸馏吸收度 | 跑自家 lint 的可读性探针（段长标准差、句长中位、打嗝句率、加粗横幅数、术语违规数），看喂进去的风格撑到第几章、是否退回默认模板 |
| 人设贴合度 | 三重声线是否真的落地，还是套了个名字的通用营养师腔。**逐章数角色词**（`大夫/诊室/门诊/候诊区/某医生`），单章超十次即人设穿帮：并行写章的产品常在后几个子任务里漏传作者身份，一本书因此出现多个叙述者（前言是传主本人、中间章变成坐诊开化验单的大夫、末章换成第三人称的科室医生）。同时核对指定章主题有没有被换掉 |
| 事实诚实度 | 逐句扫传主履历/数字，以及正文引用的研究——创作模式下的编造是这类产品的常项 |
| 跨章去重与结构控制 | `book_check.py` 类脚本查案例/研究/菜名复读率，长程记不记得前面讲过什么 |
| 科学厚度与可复核性 | 尾注/文献的真实可查性（DOI/PMID 抽检），而不是「看起来有引用」 |
| 交付完备度 | 单一裸 Word vs 出版级包（插画、三线表、双层尾注、策划书、封面） |
| 原样抄袭与串角 | 每篇样章逐段归一化重合（去空白标点、取段落前 30 字做键），报「与样章 X 重合 N/M 段（P%）」；再数样章独有的主角称呼、城市、职业、科室在新稿里出现几次，报「串角 N 次」 |

三条判分次序不能反：

- **喂范文是双刃剑，先量抄袭再量风格。** 预热把样章正文放进了对手的上下文，长稿一开写它常整段搬运而不是蒸馏风格（实测单章可到 64–79% 段落逐字重合，样章主角的称呼与城市一并继承，新书传主被写成「李主任」并被安排到样本城市的诊室坐诊）。**照抄段天然继承样章的句长与节拍，会把「风格吸收度」顶到满分**，所以顺序固定为：量原样重合率 → 剔除重合段 → 再算可读性指标 → 最后看人设与声线。只报风格分不报重合率的报告，等于给抄袭者发了风格奖。
- **它自画的自检表是主张，不是证据。** 同一份稿它会在回复里勾满「12 项全部 ✅ / 严禁捏造 / 加粗≤2 处」，而独立脚本判出 8 项 FAIL（塑出来的化验单、9 处加粗横幅、跨三章复读同一项研究）。判分只认自家 lint 输出与手抽原文；报告里并列「它自评 vs 脚本结论」这组对照，比任何形容词都有说服力。
- 两边跑**同一个脚本、同一套阈值**：门的价值在于它是外部的，不在它多严厉。
- **拿自家 lint 体检对手原稿要先补标准 YAML 头，且只比风格格。** 外部书稿没有 `chapter/part/type/title/budget` 头，直接跑先吃四条 frontmatter FAIL；`[E0xx]` 不在自家 evidence_bank 里又是一批 FAIL——这两类都是「不是自家工程」的伪 FAIL，不进对比。判定只取段落/句中位数、连续短句串、`不是…而是…` 密度、banned phrase 这些风格格，逐章表里每章两行（它 vs 我们）并列，让读者看到差距落在哪一格。

结论写法与 §7 一致：先给本质（它是什么 / 不是什么），短板落到机制，最后一句回答用户真正的问题——两条线是分工还是替代。
