# 论文转述核查（推文/博主在吹一篇研究）

触发：用户丢来一条推文/帖子，博主在里面转述一篇论文、预印本或「某公司最新研究」，问「调研一下这个」。
交付仍是聊天里的结构化答复，但一手源是**论文本身**，推文只当索引。

## 1. 先落一手论文，再评价推文

- 推文常常不给 arXiv 号。用论文英文标题的**精确短语** `web_search`，命中 `arxiv.org/abs/<id>` 最快；机构名 + 关键词也行。
- 取**最新版本**：`arxiv.org/html/<id>v<N>` 的 HTML 全文比 PDF 好抓（`web_extract` 一次拿到 Section + 附录 + 表）。先看页面顶部 `arXiv:<id>v<N> [cs.AI] <date>` 和 `Received`，确认版本和日期。
- **别信「最新发布」**：营销号常翻红几个月前的旧预印本。首版/修订日期与博主说的「刚发布」对不上时，直接写进结论第一句。
- 全文超过 `char_limit` 时按 footer 给的 offset 分段读到底，尤其用 offset 去取**附录里的表格和消融实验**——正文叙述常与表格不一致。

## 2. 拆作者单位：谁提供数据、谁在卖服务

作者列表里甲方（品牌/客户方邮箱域名）与乙方（咨询公司、实验室、乙方产品团队）混编时，写清两件事：谁是数据提供方，谁靠这套方法卖咨询。这决定这篇是「学术结论」还是「案例型销售物料」，也决定该方法对第三方的可迁移性（乙方多半不公开数据集与全部 prompt）。

## 3. 推文结论拆成原子判断，逐条回论文定位

把「他说这篇证明了 X」拆成一句一个判断，每条标注论文 Section 号 / 图表号，分三类：

| 类别 | 处理 |
|---|---|
| 原话支持 | 引原文 + 给数字，允许承认「属实」 |
| 外推过头 | 找出被偷换的对象，写明原文实际对照的是什么 |
| 无支撑 | 直接判编造，不要替它圆 |

最常见的外推模板：

- **把「问卷/打分的意图」换成「真实购买/销量」**：论文 Ground Truth 通常只是人类问卷的 5 分制打分，没有任何转化率数据。
- **把「复现了两三个维度」扩成「完美复现了所有人的所有反应」**：论文常明说某几个维度（性别、地区、族裔之类）根本没复现。
- **把「最佳锚点集/最佳子集的结果」说成「方法通用」**：最优子集往往是事后挑出来的。
- **把相关性达成率说成准确率**：`ρ = E[R_xy]/E[R_xx]` 这类「相对理论上限的比值」被转述成「准确率 90%」是口径造假，必须写清分母是什么（这里是人类自己跟自己重测的相关性上限）。

## 4. 必读论文自己的 Limitations 段

Discussion/Limitations 里作者自认的边界，通常就是推文省掉的全部水分，逐句引用比任何第三方评价都硬。高频三条：

- 关键部件（锚点语句、参考集、阈值）是在**本数据集上手工调优**过的 → 换行业/换问题会漂移。
- 某个维度复现失败 → 子群分析不能用。
- 有效性绑定预训练语料密度（该品类网上讨论多才成立）→ 冷门/全新品类不成立。

## 5. 复现实现要核范围

论文附录给的 GitHub 包一般只实现**后处理算子**（文本 → embedding → 分布），不含 prompt、数据集、评测脚本。用 `api.github.com/repos/<owner>/<repo>` 读 `created_at / pushed_at / stargazers_count / license` 判成熟度，并在结论里写清「能装的是什么、不能装的是什么」。

## 6. 表格按论文原表全量搬，含消融行

主实验表（含消融与基线）整张搬进答复，不要只挑最好看的两行。**消融行常常是全篇最有洞察的一行**：本类论文里「去掉某个关键约束后，分布相似度反而更高但排序能力崩掉」是最典型的坑——说明那个指标单独看会骗人。营销文永远不会提这一行。

## 7. 结尾两层

1. **可用价值**：借哪个具体机制落到用户自己的项目/工作流（不是「这套方法很值得学」），并指出能不能直接装。
2. **科研诚实性判断**：哪些结论现在就能用、哪些要等第三方复现、哪些对该用户所在领域根本不适用。
