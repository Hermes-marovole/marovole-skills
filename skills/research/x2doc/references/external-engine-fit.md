# 外部代码出片引擎 / Agent Skill 能不能进我们产线

触发：用户丢来一个 X 帖或 GitHub 仓库（“学一下这个项目，我想用它做视频”“分析一下值不值得用”），要一份可决策的报告。目标不是复述 README，而是回答三个问题：**它替得了我们哪一环、替不了哪一环、借哪几件东西就够**。

## 1. 动手顺序（先验证，再写报告）

1. **浅克隆只读**：`git clone --depth 1 <repo> ~/Workspace/playground/<repo>`，不 install、不改全局环境。报告里写 commit hash。
2. **前置依赖实测**：`which uv ffmpeg ffprobe playwright` + `ffmpeg -version | head -2`（确认有 `h264_videotoolbox`，Mac 上走硬编）。齐了才能说“随时可试”，缺就写清要装什么。
3. **跑它自己的门禁**，拿真实输出而不是宣传语：这类仓库多带 `lint.py` / `strip.py` / `safe.py` / `still.py`，对自带样片跑一遍。报告引用真实返回（`0 errors` 比“质量很高”有信息量）。
   - **原帖附带的那段成品视频才是最强凭据，别只读文字**：`curl -sL` 拿下 mp4，用它**同一套门禁**反测这条片子——首帧运动能量、扣掉运镜后的主体运动残差、逐段响度与刺耳频段。作者写“睡前说一句，早上醒来拿到 8 分钟成片”，只有实测过的人才配引用这句话；实测数字同时是后面 Pilot 验收的比对基准。
   - **声音那一半不要跳过**：`ffmpeg -v error -i x.mp4 -af ebur128=peak=true -f null -` 直接读 Integrated loudness（LUFS）与 True peak（dBFS）。作者文档若披露了自己的母带指标（如 `-15.8 LUFS / -1.6 dBTP`），实测落在 ±0.2 LU 内才能说“它真跑了那套母带链”，否则就是编的。**测编码后的 MP4，不测中间 WAV**——AAC 会推高真峰值，只测 WAV 的结论没有意义。
   - **它声称的“静音断口 / 停顿”必须用 50ms 步长扫 RMS 才看得见**：`ffmpeg -i x.mp4 -f s16le -ac 2 -ar 48000 -` 解码成 numpy，切片后算 `20*log10(sqrt(mean(x**2)))`。真正的 cut 会掉到 −80 dBFS 以下（底噪位），前后各一小节却是 −15 dBFS 上下；整段平均或 250ms 窗口都会把它抹平。抓到静音点后紧跟的全片峰值就是所谓“最响那一刀”。
   - **抽单帧做接触表时 `-vsync 0` 在新的 ffmpeg 已被移除**，改用 `-fps_mode passthrough`；否则带 `select=` 多帧输出会直接 `Unrecognized option 'vsync'` 退出，而外层 `|| echo` 会把失败伪装成 exit 0。
   - **把作者文档自述的量化项当反测清单**：LUFS / 真峰值 / 静音深度 / RGB 距离 / 速度上限 / 首尾帧差——越具体越可验。逐条打勾或打叉，比“画面很精美”有信息量，也是报告里最硬的一段；顺带能看出它经历过几轮返工（自述轮次表照录，别当成“一句 prompt 出片”）。
   - **用它的门禁测它的样片时，跑出 FAIL 是全篇最有说服力的一段，别藏也别当差评**：作者的 Showreel 被自己的 `check_render.py` 抓到某处 `2.33s` 画面静止（阈值 `1.5s`），说明门禁不是摆设。立刻抽那一秒的帧确认脚本判得对（是不是真有一张卡片停住不动），报告写「6/7 PASS + 1 FAIL 及 FAIL 的具体内容」。全 PASS 只证明脚本能跑，一条经得起复看的 FAIL 才证明它有牙。
   - **自带测试集有失败项时，先按同一根因归类再下结论**：52 项里 6 项失败、且全报 `No such filter: 'drawtext'`，那是同一条环境缺口（Homebrew ffmpeg 未编 `libfreetype`），不是 6 个仓库缺陷；同理，脚本把已装的 Blender 报成未安装，多是候选路径只写了 `C:\Program Files`。报告写「N 项通过 / M 项因本机某依赖缺失失败（根因一句话）+ 绕法」，例如打时间戳改用 Pillow 在内存画完再存图，绕开 `drawtext`。把环境缺口写成「仓库质量差」，或者因为缺一个滤镜就否掉整个工具，都是错的判断。
   - **长片子分次调用**：400 秒以上的片子，拼几十格接触表 + 逐分钟运动残差 + 逐段响度是分钟级工作量。不要把两三条重活串进一次 180 秒的前台 shell 调用（第一条就超时，后面的数字全丢还得重跑）；拆成独立调用、给足 timeout 或后台跑，产物落盘再读回。
4. **读它的 references/ 而不是 README**：留存数据、成本账本、踩坑清单基本都在 `references/`；README 只有卖点。作者自述的成本/时长要标“作者披露”，与自己实测分开写。
5. **本地 serve 给一个 3 分钟入口**：一条启动命令 + 三个最该看的样片 URL，别让用户自己翻目录。

## 2. 报告必须有的四块

1. **形态映射表**：引擎支持哪几种成片形态（横屏课 / 绘本 / 纪录片 / 竖屏短片）→ 各对应我们哪条线、哪类选题。列：形态 | 画布 | 视觉语法 | 样片 | 我们的用途。
2. **取舍表（对我们现有栈）**：一行一个维度（单条出片速度 / 声画卡点精度 / 一源多出 / 史料与地理素材 / 中文支持），列“我们现有（xilo / huashu / dashi）| 它 | 结论：谁强·怎么配合”。结论要明确到“日更单条继续用 X，不要为每条小片套它全家桶”这种程度。
3. **中文落地必改项**（见 §3）。
4. **成本与周期**：分三栏——外部 API（TTS / 生图）、本地渲染（免费，只花机器时间）、LLM token（真正大头，常是 $10–18/章或千万级 token）。只报“免费开源”是误导。

收尾给**三步低成本验证**：看样片 → 单条 90 秒 Pilot 实测 → 满意后只抽 2–3 个机制合入现有管线。写清“不建议一上来改写现有 skill”。

## 3. 中文视频必改的四项（直接套原版模板必踩）

| 项 | 病灶 | 改法 |
|---|---|---|
| 配音 / 词对齐 | 基于 whisper 的逐词对齐按空格分词，中日文无空格 → 锚点全错位 | 走 Edge TTS 路线（如 `tts.py` + `zh-CN-YunxiNeural` / `zh-CN-XiaoxiaoNeural`），有中文字符级 WordBoundary；**但如果项目已定音为既有品牌配音（`eleven_v4`，带字级时间戳），不要为迁就新引擎换嗓子**——继续用现有配音与时间戳，只拿它的声学处理和人声介质化 |
| 字体 | 默认锁死纯拉丁字体，且启动时 `await` 字体加载 | 在 `fonts.css` 与 SANS / SERIF 常量加 `"PingFang SC","Noto Sans CJK SC"` / `"Songti SC"` |
| 语速 / 时长估算 | 按英文 ~2.6 词/秒 排拍 | 中文按 **3.8–4.5 字/秒** 重算每拍 |
| 画幅与角标 | 默认 9:16 + 导出自动打 `AI ILLUSTRATION` 角标 | 画幅以 video-common 的 **2:3 1080×1620** 为准（9:16 上下各裁 150px 即可，文字安全区本就在中间）；导出加 `--no-tags`，AI 声明只放发布 metadata |

## 4. 值得直接借的机制（跨引擎通用）

**先看这三类能单独调用的脚本**（不依赖它的渲染层，能直接对我们现有产线的成品 MP4 或素材跑，比整套搬划算得多）：

| 类别 | 它替我们干什么 | 为什么值钱 |
|---|---|---|
| 素材库存探针 + 许可台账 | 开工前 20 秒并发数一遍 Wikimedia / Internet Archive / Met / AIC / NASA / 开放音效库里，“某个真实人物或事件”到底有多少可用公有领域素材，选中即下载并写 `LICENSES.csv` 与简介致谢行 | 把“找得到素材吗”从开拍后的意外变成开工前的决策；台账顺带解决了发布合规 |
| 人声介质化 | TTS 干声过一遍高通 / 去齿音 / 存在感提升 / 轻压缩，再按内容选介质（贴耳、磁带、电台、电话）与空间（干、房间、大厅），引语单独换介质 | 这是“干瘪 AI 读书声”与“纪录片旁白”之间唯一的差；不换嗓子，只叠一层处理 |
| 去水分的机器门禁 | 扣掉运镜后的主体运动残差（抓“只有镜头在动”的死图）、禁破折号与英文 AI 套话的词检、逐景 2–5 kHz 刺耳度 | 三道都能在交付前跑，零成本拦住最丢人的两类错 |

其余可借件：

- **词级锚点 + 纯函数时钟**：剧本把 `[[mark]]` 写在要触发画面的那个词前（`This doctor [[warned]]warned about...`），TTS 跑出每词秒数写进 `timings.js`，画面代码用 `m('mark')` 取值。缓存按文本 SHA1 索引 → 挪锚点只重算时间表，不重新调 TTS 花钱。这是把“卡点”从估算变成查表的关键。
- **转场预卷（LEAD）**：竖屏引擎把 `m(k)` 统一提前约 `0.22s` 触发，让 0.2s 上滑 / 0.26s 横甩在听见该词时落定。通用式：**预卷 ≈ 转场时长 − 0.05s**。
- **首帧必须已经在动 + 第一句就给结论**：同题材实测首秒留存 57.8%（运动中画面直说结论）对 12.8%（静态标题卡 + 铺垫）。纯文字开场卡禁掉。
- **平台安全区检查器**：竖屏顶 120px / 底 300px / 右侧按钮区（y 700–1300）被平台 UI 遮挡；文字锁在 `x:50–810, y:130–1290`，超宽自动缩字号，脚本逐拍抽检越界。
- **死画面检查器**：6 秒内 1.0→1.08 的推镜在手机上等于死图；长镜头推镜必须 ≥15% 或直接切镜，脚本扫全片报无变化区间。
- **逐帧确定性导出**：不录屏，按 `f/fps` 逐帧 seek 截图，多个无头 Chromium 并发（开 GPU），ffmpeg `h264_videotoolbox` 编 1080p + BT.709 修正 + `.srt`。画面是 t 的纯函数，改一个数重渲即可。
- **来源台账 + 自动角标**：抓公有领域素材时同步写 `SOURCES.tsv`（文件名 / 作者 / 协议 / 原链 / 年代），画面按需打灰色角标；与“片内每个数字须有本次原文”同构，可整段搬。
- **配乐休止符裁剪**：自动剪掉配乐里的静音坑与弱尾音并把尾音卡在全片结束帧；人声起时 BGM duck 到 30%；旁白统一 `-14 LUFS`、峰值 `-1.5 dBTP`。
- **3D 地球 → 纸质地图无缝交接**：同一 `{lon,lat,H}` 视角从夜景地球俯冲切 2D 省界 / 城市图，做产业地理、科技史选题是现成件。
- **两轮导演审片**：Round 1 只看接触表（不给代码）挑“嘴里讲 A、画面停在 B”；Round 2 看导出 MP4，每 0.5s 抽帧 + Whisper 反跑音轨对剧本。人眼自检常漏，值得照抄成独立子代理。

## 5. 成本与上下文陷阱

- 单会话反复读巨大接触表图可烧到千万级 token；正确做法是 Coordinator 只看摘要 + 按步骤派短命 subagent（一个 subagent 只做一个场景）。
- 一章插画级内容的 LLM 成本约 $10–18，**不适合日更单条**；日更继续用轻量单页渲染。
- 三栏成本必须分开写，用户真正看的是 LLM token 那栏。

## 6. 反模式

- 只复述 README 功能列表 → 用户拿不到决策。
- 建议直接替换现有主力管线 → 与“现有 skill 能出活就直接复用”的偏好相反；默认结论是**借件不换栈**。
- **把作者的赛道当成推荐** → 作者举例的细分（超自然、历史奇案、事件复盘）常与用户的变现漏斗零交集：看这类片的人不会变成付费用户，RPM 也低。报告里必须把「借形态（调查纪录片的视觉语法与悬念结构）」与「不借赛道」分开写，并给出 2–3 个落在用户已有实测数据和英文搜索需求上的选题方向。
- 把作者的宣传数字（“一条 prompt 出片”“全自动”）当事实；标“作者自述”并给出自己实跑的证据。
- 忘了查同主题旧报告：`ls docs | grep x2doc` 之后再动笔，同族引擎互相链接而不是各写一份。
