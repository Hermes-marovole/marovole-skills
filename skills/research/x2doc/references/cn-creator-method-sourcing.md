# 中文博主方法论取材与归档

用于「学这个博主」「同样方法再拆一篇」——目标不是转述一条帖子，而是拿到这个人**当前最完整的公开方法论**，落成可持续复用的方向指导。

## 取材顺序（由便宜到贵，命中即停）

1. **单帖正文**：`curl https://api.fxtwitter.com/<handle>/status/<id>`，判 `tweet.article` 是否存在；存在就按 SKILL.md 的 entityMap 配方渲染全文（`header-two` / list / `atomic` 里的 MARKDOWN/TWEET/MEDIA/LINK）。
2. **文章归档站**（找"这个人一共发过哪几篇长文"）：搜 `"<handle>" <主题>`，常见镜像 `jxxy.net/ai/articles/<handle>-<status_id>/`、`zhongwenx.com/creators/<handle>`、`xbangdan.com/account/<handle>/`。先拿到**篇目清单**，再判断用户要找的那篇到底存不存在。
3. **Space / 直播 / 播客逐字稿**（往往是最完整的一版）：`audio.eatmoreduck.com/space/<id>/` 这类页面自带说话人分离、时间戳、可搜索转写。用 `web_search "<handle> <主题> 逐字稿"` 命中；一场 90 分钟分享的机制密度普遍高于一篇长文，且包含问答段的真实卡点。
4. **时间线镜像翻页（最后手段）**：`teapawt.org/<handle>?cursor=...` 可纯 curl 逐页抓、不消耗 Firecrawl 额度，但它是有深度和速率上限的——几十页后空响应或限流，且到不了账号最早期。**不要为了找一篇"承诺要发"的帖子去翻几十页时间线**，代价与收益完全不成比例。

## 源可信度审计（针对"卖课型"博主）

这类作者的方法论本身就是其漏斗：

- 免费长文 / 免费分享 = **引流款**；付费社群、一对一、付费观看位 = 标准款/利润款。判断时把"他为什么要公开这些"算进去。
- 越是关键的环节（导流路径、投流预算、起量节奏）越会被扣住；"全套方法都公开了"本身是营销话术。把**披露深度有限**写成结论的一条，而不是当成自己没查全。
- 承诺型内容（"阅读过十万就更新 XX 教程"）经常不兑现——先查篇目清单，再决定是否投入搜索。
- 自述数字（第一桶金、单条播放、月收入、卖课规模）一律标注为自述；方向可信 ≠ 量级可信。他持续在经营这门生意这一点，才是"方法能跑通"的真正证据。
- 他的案例是他自己的赛道复盘：**抄商业结构，不抄起号姿势**。照抄/矩阵号/养号脚本这类姿势常与用户红线（原创、真实账号）直接冲突。

## 交付：两篇 Obsidian 笔记（成对存在）

目录 `03-Areas/<领域>/`（自媒体类为 `03-Areas/自媒体/`），受控标签：

| 文件 | tags | 内容 |
|---|---|---|
| `<来源>-<主题>-逐字稿.md` | `type/source`, `area/*`, `status/reference` | 文件头写来源 URL / 主讲 / 时长 / 转写质量警告；**章节时间表**（`| 时间 | 章节 |`）；按章节忠实重述，保留他的原话切口与自造词 |
| `<领域>方向指导-基于<来源><主题>.md` | `type/guide`, `area/*`, `status/active` | 拆解 + 落到我们的执行准则 |

方向指导的固定骨架：

1. **定位警告（先读）**——样本量、自述数字、他是这门生意的卖方、哪些是红线姿势。
2. **一句话**：他这套到底是什么。
3. **增量机制**：按对用户的价值排序，只写这篇相对已有笔记**新增**的部分，重复的合并成一句"与 X 文互相印证"。
4. **映射表**：`他的概念 | 我们的对应物 | 动作`——每个概念都要落到用户当前真实在跑的东西（开源仓、社群、咨询、选题法、slogan）。
5. **冲突点（明确不抄）**：逐条列出与用户红线冲突的战术及冲突点；新手向教程尤其容易与"原创 IP"路线对立。
6. **已覆盖的 skill / 管线**：查 `skills_list`，把方法映射到已装技能，别让用户再去找工具。
7. **待验证假设 + 风险**：可执行的验证动作（含 A/B 设计），和自述/口径问题。
8. **结论**：这篇在他的方法论体系里占哪一层（平台算法层 / 商业结构层），与已有笔记如何互补。

命名直接带主题，不写"终版"；同一博主多篇按"平台层/商业层"在结论里分工，不合并成一篇大杂烩。
