# 病毒式信息图 / 榜单打假（tier list、N 个必听必看必用、对比表）

## 何时用
用户丢来一张高互动截图或信息图（六档分级表、"Top N podcasts/tools/books"、对比矩阵），要你据此做内容、或在稿件/判断单里引用它。这类图几乎都是批量拼装的，收藏量越高越没人核过——逐格核一遍本身就是内容，而且比转译更容易出差异化。

## 程序
1. **先转录成 evidence**：把图上每一格的文字逐行写进 `sources/image_transcript.txt`，**保留图上的错误原样**（错的人名、错的主持人、错的机构标），再 `grounding.py image --date <D> <图片URL> --text <transcript> --published <发帖日>` 登记。转录时不要"顺手改对"，改对了就没有对照物，也核不出错。编号写进每一行（`13. The Brain Science Podcast — Gina Rippon`），后面 `facts.json` 引用同一行的原文。
2. **每格核三件事**，缺一不可：
   - **存在性**：这个节目/产品/机构真的存在、名字真是这么写的吗？
   - **归属**：作者 / 主持人 / 出品方是谁？图上署的人真的是它的作者吗？
   - **状态**：还在更新吗？停更 / 完结 / 关停 / 被收购 / 脱离原机构是哪一年？
3. **维基百科 infobox 一页能同时核这三件**（首播与完结日期、hosted by、parent company），优先查它；官方站（podcast 官网 about 页、公司 help center）用来核 Wikipedia 滞后的「停更 / 关停」状态。**一手源 BAD（帮助中心、财经站常被墙）就换一个能读的媒体源核同一件事**，不要在坏源上反复重试。
4. **只把有原文引语的错误写进稿子**，一条错误 = 一条 facts 台账条目（原图引语 + 一手源引语 + URL）；不推断制图动机（没看到原帖自述就不要写「这是 AI 生成的」，写「我的判断是：」也不行——动机不是事实）。
5. **标题只写已核实的条数**（「我查出 6 处」），不写全称判断（「这一半都是假的」）。全称断言要逐格核完 30 格才能成立，核不完就是夸大，review 和读者都会打回。

## 固定错误类型（按出现频率排）
| 类型 | 表现 | 核法 |
|---|---|---|
| 张冠李戴 | 把创办/主持多年的真人换成同领域另一个名人 | 官方 about 页的 host 一句 |
| 凭空节目名 | 把公司名、投资标的、App 名当成节目名挂在某人名下 | 本人维基的"podcast"段 + 该名字的百科/新闻 |
| 机构归属过期 | 早已独立/被收购，图上还贴着原台标或母公司 | 维基的 "independent / left X in <年>" 句 |
| 已完结当现任 | 停更 3–15 年的节目混进"日常订阅" | 维基的 original release 区间 |
| 母公司已解散 | 节目归属的厂牌本身已关停 | 厂牌维基的 defunct 年份 |

## Pitfalls
- **停更日期必须写年月并给出**（「2012 年 5 月完结」「2023 年 12 月停更」），只写「已经停更」读者会当成最近的事，而这类节目往往停了三五年以上，时间跨度本身就是反差点。
- **不要因为一格错了就推定整张图全错**：核出 5–6 处就写 5–6 处，剩下的如实写「其余没核」。反过来也不要放过"看着没问题"的格子——归属错误（谁做的）比时效错误更难被读者发现，也是最容易一击致命的。
- **这类图的收藏量常高于点赞量**（收藏/点赞 > 1.2 就是典型"存了不看"），这是选题角度而不是错误：把"你收藏的清单没人核过"做成钩子，比逐条纠错更有共鸣。
- 图中人物头像、Logo 与文字不符时，以文字为准去核，不要把"这张脸不是他"当事实写——图像识别的结论不能进稿。
