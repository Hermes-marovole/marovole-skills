# Market, Financial & GTM Intelligence (市场、招股书财报与获客一手情报)

## When to Use

当用户需要进行以下任一深度的商业与产品研究时调用本技能：
- **市场与赛道调研**：测算真实市场规模（TAM/SAM/SOM）、拆解产业链毛利与分润结构、寻找未被满足的细分切口（Wedge）。
- **行业巨头招股书与财报解剖**：从美股（S-1/10-K/20-F）、港股（港交所披露易招股书/沙利文灼识行业概览/年报）、A股（招股说明书/审核问询函回复）提取真实毛利率、销售费用率、获客成本（CAC）、留存复购率（Cohort）与风险因素。
- **竞品全景与获客漏斗拆解**：扫描竞品网站目录树（Sitemap）、拆解测评问卷（Quiz）与付费墙（Paywall）、逆向分析其 SEO/投流钩子与招聘 JD 暴露的产品路线图。
- **用户差评与迁移痛点挖掘（VOC）**：抓取京东、Amazon、小红书、Reddit、App Store、G2 的 1-3 星差评与切换原话，指导产品功能优先级。
- **第三方集成面审计（API / SDK / MCP / 开放平台）**：用户问「这个产品有 API 吗 / 他们有 MCP 吗 / 能不能接进 Claude 或我们的 Agent」时，按三态（接口存在 / 文档在线 / 官方支持）实测判定，不靠搜索摘要和官网宣传语下结论。方法论见 `references/integration-surface-audit.md`。
- **人口与宏观基数调研**：用户问「中国有多少 X 人群」（育龄女性、慢病患者、银发人口、新生儿）时，按 `references/china-official-statistics.md` 的官方口径取数与时点标注，不拿自媒体二手数交差。
- **网传案例与匿名案例声称核验**：用户丢来一条 X 帖 / 播客切片 / 公众号长文说「调研一下这个」，而其中的主体（「某几十亿营收的大卖」）查不到具名认领时，按 `references/hype-claim-verification.md` 做三层核验（个案主体 / 行业大盘 / 生态落地），并交付「核真伪 → 纵向拆底座 → 横向选型矩阵 → 去滤镜深水区 → 对用户的判断」五段。既不复述推文数字当事实，也不因主体不可证伪就把整条失真趋势一起扔掉。
- **模型 / 产品发布与「开源」声明核验**：厂商开大会「连发 N 款」、通稿写「全面开源」「可本地部署」「行业第一」，用户接着问「哪里能调/能不能用」，按 `references/model-release-audit.md` 逐仓落四档档位、回模型卡核硬件门槛、按三态查托管 API 与免费期、复原完整基准表并复原榜单覆盖矩阵，最后收束成「不自建 → 三条路线矩阵 → DO/DON'T」。
- **单仓开源项目 / 工具底座尽调**：用户丢一个 GitHub 仓库或一条介绍帖问「这个工具怎么样、能不能用在我们场景」时，按 `references/oss-project-dossier.md` 走四层取证（GitHub API 元数据 → raw docs 架构 → 本机 `uvx`/`npx` 黑盒实测 → 许可证与开源/闭源切分），实测结论一律落成 `x/N` 召回表，交付 KPI 卡 + 两条判断框 + 适用/不适用清单。Star 数与 README 宣称都不算可用性证据。

## Goal

为产品方向定义、核心功能切入点（Feature Wedge）和获客增长（GTM）提供**100% 源自一手抓取数据**的决策依据。彻底杜绝拿二手自媒体软文或拍脑袋宏观大数交差的「表演式调研（Research Theater）」。

核心融合 6 大情报工程模块：
1. **行业巨头招股书（S-1 / 港交所 H 股 / A 股）与财报（10-K / 20-F / 年报 / 电话会）深度解剖**
2. **TAM / SAM / SOM 双向三角定量校验（Top-Down × Bottom-Up Triangulation）**
3. **并发失忆侦察兵（Amnesiac Competitor Scouts）：网站拓扑、付费墙漏斗、SEO 与招聘信号逆向**
4. **一手用户差评与迁移原话挖掘（1-3 Star Review & Switching VOC Mining）**
5. **魔鬼代言人反方压测（Devil's Advocate Challenge）**
6. **Grounding 原文引用台账 + 浅色简洁一页到底 HTML 交付**

## Success Criteria (全维度大样本默认门禁 — 每次调研必须一次到位，不许等用户追问才补抓)

- **大样本一手数据硬门槛（默认 ≥300–1,000 条原始记录落盘）**：每次调研必须在 `~/.hermes/cache/scratch/<topic>_research/` 下落盘保存原始 JSON/MD 抓取数据包，严禁只搜 5 条网页摘要就写报告。
- **十四维全覆盖（缺一不可，由 `intent` / `ecommerce` / `hiring` / `pubmed` / `radar` / `queries` / `size` 7 大子命令驱动）**：
  1. **自家产品契约审计**：先读本地代码仓/线上文案，列出「教科书视角 vs 用户任务视角」病灶对照表；
  2. **6 大平台实时搜索动作 (`intent`)**：跑满 3–5 个核心词根（200+ 条下拉联想词）；
  3. **电商交易与买家评论 (`ecommerce` + `opencli`)**：同人群下对比 5 种交付形态（纯视频/静态表/图书 vs 1v1 服务 vs 高毛利实物）的真实售价、付款人数与 80+ 条买家评论原话；
  4. **1688 源头供应链 BOM 底价 (`opencli 1688`)**：抓取 30–60 家 OEM/ODM 代工厂批发价与回头率，核算终端溢价倍数；
  5. **闲鱼（Goofish）二手弃坑率与灰产代充监测**：通过 `opencli xianyu` 或 `site:goofish.com` / `site:smzdm.com` 抓取二手抛售价格、弃坑理由与会员代充价梯；
  6. **国内外行业招聘 JD 逆向 (`hiring`)**：从智联招聘/猎聘/BOSS直聘及海外 Greenhouse/Lever/Primary VC 抓取真实 JD 原文，拆出竞品私域 SOP、单教练管理人数上限（Caseload）与单客人工计件成本（如 $5/user/mo）；
  7. **四大标杆招股书/财报 + 社媒高赞评论 + PubMed 临床文献 (`queries` + `pubmed`)**：抓取 200+ 条 B站/小红书/知乎/Reddit 高赞用户原话，以及 20–50 篇 PubMed/Europe PMC 最新临床医学文献（带 PMID/DOI）；
  8. **消费者维权与退费黑洞 (`radar` 维度 1：黑猫投诉 / 12315)**：抓取竞品在黑猫投诉/12315 上的真实退费金额、自动扣费纠纷与诱导消费客诉，作为产品风控与信任背书设计底线；
  9. **国家部委政策红利与公立医院风向 (`radar` 维度 2：卫健委 / 临床指南)**：抓取最新国家政策（如国家卫健委“体重管理年”三年行动与指导原则），对齐合规借势话术；
  10. **一二线高净值人群长音频心智 (`radar` 维度 3：小宇宙播客 Show Notes 与高赞评论)**：抓取小宇宙播客单集大纲与评论区原话，识别高认知女性对“制造焦虑话术”的反感点与社群导流钩子；
  11. **全球标杆 D2C 商城 SKU 命名与套餐打包逆向 (`radar` 维度 4：如 `shop.joinmidi.com`)**：抓取海外标杆独立站全量 SKU、症状提问式 Bullet Points、3 件套 Bundle 锚定与 Subscribe & Save 20%–30% 订阅锁客机制；
  12. **激进替代方案翻车与停药反弹黄金承接窗 (`radar` 维度 5：如 GLP-1 减肥针停药反弹 / 医美埋线)**：抓取 STEP-1 / SURMOUNT-4 / BMJ 停药反弹率、真实世界 3 年留存率（仅 1/12）及滥用急诊案例，找到承接“停针防反弹”高付费人群的切口；
  13. **达人分销与精选联盟佣金结构 (`radar` 维度 6：蝉妈妈 / 精选联盟)**：摸清抖音/视频号带货高佣比例，测算自建内容矩阵 vs 达人分销的渠道成本；
  14. **TAM/SAM/SOM 双向三角校验 (`size`) + 1,000 人池单位经济模型 + Grounding 引用台账 (`sources.py verify`)**。
- 每一条市场规模、毛利率、CAC、LTV、留存率、价格、招聘 KPI 与用户原话，均附有本次实际抓取的 URL 与逐字引语（通过 `sources.py verify` 输出 `citations OK`）。
- 最终输出包含：**浅色简洁一页到底的独立 HTML 报告** + **Markdown 存档** + **本地原始 JSON 样本库路径说明**。

## Procedure (七步标准作业程序)

### Step 0: 环境自检与安装验收 (Stack Verification — 写任何检索式之前先跑)

新环境、换机、同事按 handoff 装完之后，**先跑验收脚本，再开工**。手写的「环境已就绪」不算验收：每项检查都必须真实执行代码路径，跑不通就报 FAIL，而不是凭 key 存在推断可用。

```bash
python3 ~/.hermes/skills/research/market-intelligence/scripts/verify_stack.py
# 默认探针词可换：--topic "<核心品类词>"  机器可读：--json
```

脚本覆盖六层：CLI 二进制（opencli/dokobot/tinyfish/uvx）、router key 非空校验（占位符与空串都判 EMPTY）、**逐引擎路由并比对返回的 `engine` 字段**、extract 双路径（firecrawl→jina）、`intent` 下拉词与电商购买框、`size` 三角校验自测。

读结果时只认两件事：
- **`FAILOVER` 不等于 `OK`**：请 `--engine ddgs` 却是别的引擎答的，说明该引擎当前不可用，不能写进「5/5 全绿」。路由器的 `--engine` 是**起点偏好**，不是硬绑；链路会静默降级到下一个能出结果的引擎，只有 JSON 里的 `engine` 字段告诉你实际是谁答的。
- **key 存在 ≠ 能用**：`PARALLEL_API_KEY=` 这种空值行能骗过所有「key 是否配置」的检查，然后 401。

验收通过再进 Step 1；任何 required FAIL 都先去修环境，不要带着半瘫的采集链路开始抓数——用降级链路跑出来的样本量与覆盖面会静默不足，最后表现为「数据太少」而不是「工具坏了」。

### Step 1: 行业巨头招股书与财报解剖 (Prospectus & Earnings Teardown)

**核心认知**：自媒体文章全是公关噪音，只有经过审计师和律所签字负法律责任的**招股书（Prospectus / S-1 / F-1）**和**年度财报（10-K / 20-F / 年报）**才是免费的百万美金级一手数据库。

使用 `python3 $MI_TOOL queries --company "<公司/赛道>" --market us|hk|cn` 生成精准检索式，并通过 `search.py --engine serper` 或 `firecrawl` 抓取原文，重点解剖以下 **5 个黄金章节**：

| 必拆章节 | 英文/港美股定位词 | 中文/港A股定位词 | 提取什么一手数据 | 对我们的指导意义 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 行业概览（白嫖顶级付费研报）** | `Industry Overview` / `Market Opportunity` | `行业概览`（弗若斯特沙利文 / 灼识咨询 / 艾瑞 / 欧睿） | 细分赛道真实盘子、CAGR、渗透率、产业链上下游分润比例、前五大玩家市占率（CR5）。 | **定方向**：看清钱在产业链哪一层被赚走了（生产 vs 渠道 vs 品牌 vs 订阅服务）。 |
| **2. 业务与产品矩阵（解剖现金牛）** | `Business` / `Our Products` / `Cohort` | `业务` / `主要产品及服务` / `客户留存` | 各产品线/SKU 营收占比、复购率（Retention / Net Dollar Retention）、平均客单价（ARPU/AOV）、生命周期（LTV）。 | **定功能**：巨头靠哪个单品引流（Loss Leader），靠哪个高毛利服务/复购赚钱？ |
| **3. 财务与销售费用拆解（透视获客 ROI）** | `MD&A` / `Selling and Marketing Expenses` | `财务信息` / `销售及营销开支明细` | 毛利率（Gross Margin）、销售费用率（S&M % of Revenue）、**获客费用的具体去向**（投流买量 vs 达人佣金 vs 线下渠道 vs 研发人员薪酬）、回本周期（Payback Period）。 | **定获客**：如果巨头买量费用率高达 50%-60% 导致微利，我们绝不能正面硬刚付费投流，必须走内容/SEO/私域/钩子工具差异化获客。 |
| **4. 风险因素（管理层被迫说真话的地方）** | `Item 1A. Risk Factors` | `风险因素` | 客户流失原因、单一渠道/平台依赖度、退货/投诉率、合规监管红线（如保健品宣传边界、FDA/NMPA/广告法风险）、技术迭代威胁。 | **找切口（Wedge）**：巨头因为船大掉不了头或害怕合规而不敢碰、但用户极度渴望的痛点，就是我们的破局点。 |
| **5. 财报电话会 Q&A（华尔街逼问的最新趋势）** | `Earnings Call Transcript` / `Q&A` | `业绩电话会实录` / `投资者关系问答` | 分析师尖锐追问的增长放缓原因、最新一个季度什么新功能/新渠道转化率最高、管理层未来 12 个月砍掉了什么业务、重注什么方向。 | **抢时效**：比静态行业报告领先 6-12 个月感知一线冷暖。 |

> **参考手册**：详细财务指标反推公式（如从销售费用与新增付费用户反推真实 CAC）见 `references/prospectus-earnings-playbook.md`。

### Step 2: 市场规模双向三角校验 (TAM / SAM / SOM Triangulation)

严禁只报一个“XX 行业万亿市场”的 Top-Down 大数。必须运行 `market_intel_tool.py size` 同时计算两条路径：
1. **Top-Down（自上而下）**：招股书/智库总盘子（TAM） × 产品可服务范围比例（SAM %） × 1-3 年现实市占率（SOM %）。
2. **Bottom-Up（自下而上）**：可触达目标人群/企业基数 × 付费转化率 × 年均客单价（ACV / ARPU）。
3. **三角校验铁律**：若 `Top-Down SOM` 与 `Bottom-Up SOM` 相差超过 **3 倍**，脚本将触发 `TRIANGULATION_FAILED` 警告，必须重新核查客单价或真实受众基数，绝不取平均数掩盖分歧。
4. **两侧必须同口径：混口径算出来的「收敛」是假收敛**。Top-Down 与 Bottom-Up 的 SOM 只能是同一种钱——要么两侧都是平台净留存收入，要么两侧都是 GMV。拿「板块总盘子 × 1%」的 GMV 份额去比「席位 × ACV」的净订阅收入，比值毫无意义，却会算出一个漂亮的 1.x 倍「通过」；参数再动一动，同一套模型又能算出「10 倍天花板」。两类口径都要交时，**分开跑两次 `size`（净收入版 / GMV 版），各报各的偏离比**，再单独写明 GMV 折算成净留存用的是哪一个百分比。
5. **「双向收敛」不是独立验证**：两条路径共用可触达基数、转化率、人均消费这些主观锚点时，收敛只证明算术自洽，不证明假设为真。报告里写「估算对照」而不是「三角验证」，并把每个假设标成「证据 / 假设 / 待实测」三档；试点能测的写清测法与通过门槛。
6. **人群基数分母必须落到官方实测口径**：TAM/SAM 的目标人群分母（育龄女性、慢病人群、老年人口等）先按 `references/china-official-statistics.md` 取国家统计局口径与时点，再乘渗透率。分母用错口径（如把 15—49 岁育龄女性当孕产人群）会让整张 TAM 表失真一个量级。

### Step 3: 并发失忆侦察兵 — 竞品拓扑与漏斗逆向 (Parallel Competitor Scouts)

锁定 3–5 家高利润/高增长标杆竞品（先用 `dbs-benchmark` 五重过滤排除噪音）。用 `delegate_task` 为每家竞品派生一个独立的子 Agent（或分批脚本），互不串味，严格按 `references/competitor-dossier-schema.md` 抓取以下 5 维一手信号：

1. **全站目录树扫描 (`firecrawl_map`)**：
   - 先看 URL 结构再看文案：是否有 `/quiz/`（测评漏斗）、`/tools/` 或 `/calculator/`（免费工具 SEO 获客）、`/vs/` 或 `/alternatives/`（竞品词截流）、`/enterprise`（向 B 端转型）？
2. **Onboarding → Paywall 付费墙九维拆解**：
   - 首屏 5 秒价值主张（逐字摘录 Hero Tagline & CTA）、启动到付费墙经过几个问题节点、订阅周期比例（月/季/年）、价格锚定与风险消除话术（退款承诺/专家背书）。
3. **SEO 与付费买量获客情报**：
   - 谁在核心痛点词排前 3？哪些长青广告素材在 Meta Ad Library / Google Ads Transparency Center / 抖音小红书连续投放超 30 天（存活期 >30 天 = ROI 跑通）？
4. **招聘信号逆向产品路线图与人效底牌 (`market_intel_tool.py hiring`)**：
   - 运行 `python3 $MI_TOOL hiring "<角色/赛道词>" -c "<竞品名>"` 生成国内外招聘平台穿透检索式，并用 `web_extract` 抓取智联招聘（`zhaopin.com/jobdetail/...`）、猎聘、BOSS直聘、Greenhouse（`job-boards.greenhouse.io/<company>`）、Lever、Ashby、Primary VC Job Board 上的 JD 全文。
   - **必拆三大机密指标**：
     1. **私域 SOP 与转化闭环路径**：从国内「私域营养师 / 训练营班主任 / 用户增长运营」JD 的岗位职责中，直接提取对手的完整转化链路（如“视频号公域引流 → 企微标签分层管理 → 降糖/减脂训练营 → 服务包复购裂变”）；
     2. **一线顾问人效上限（Active Caseload）与单客人工成本**：从海外/国内教练 JD 中提取单人同时管理客户数（如 Noom Mindset Coach JD 明确写明 `Active Caseload: Up to 500 users`，响应 SLA `<1 hour`，计件薪酬 `$5 per user per month`）及国内顾问底薪+提成比例（如兴趣岛开一单 1880 元提成 94 元 = 5% 提成率），直接用于测算我们自己的单位经济模型（Unit Economics）；
     3. **高薪研发与高管岗位暴露的未来半年战略**：如年薪 $230K–$325K 招聘 `Clinical AI Director` 与 `Growth & Supplement Commerce Director`，直接证明对手正把重兵压在 Agentic AI 赋能顾问与补剂电商闭环。
5. **诚实记录“对手赢在哪里（Where They Win）”**：
   - 每份竞品档案必须写明对手最强的壁垒，禁止单方面贬低竞品。
6. **标的/竞品的产品力拆解（Product Teardown）——与资本、估值、ARR 同级的必答章节**：
   - 以公司为对象的调研（投资尽调、竞品分析、供应商选型），只写融资估值、ARR、商业模式、监管风险一定会被打回：“产品怎么样也很重要”。产品拆解不是附录，是独立论证章节，需覆盖 ①产品矩阵与定位 ②按真实生产工序排序的工作流解剖（每步的输入/输出/失败模式）③独门功能 vs 通用能力 ④实测硬伤、定价陷阱与适用边界 ⑤同类按**生产工序**（不是功能清单）逐项横评。
   - 证据优先级：逐帧实操教程 > 第三方上机测评 > 官方 docs/changelog > 官方 features/pricing 页（只能当“厂商自述”）。方法、证据层级表与八维横评模板见 `references/product-teardown-playbook.md`。
   - **产品是 App 时，必须装机走一遍**：网页与商店页看不到付费墙叠压、默认选中档位、售前方案与进首页后的真实预算差、AI 助手的实际答法。用 MuMuPlayer Pro（国内 App）+ ADB + 无障碍节点树抓取，流程、像素取证与六道工序横评见 `references/app-emulator-teardown.md`。
   - **对手已经是 Agent-native（对外开 API / MCP）时，接口返回的 JSON 才是最高等级证据**：`llms.txt`、`/.well-known/mcp/server-card.json`、`openapi.json` 给的是字段级事实（评分维度与权重、每份成本、剂量区间、工具读写边界），比网页文案硬一档，也便于逐条核验。取证顺序、JSON-RPC 直调与参数探测见 `references/integration-surface-audit.md` 第六节。
7. **企业工商穿透、历史股权逆向、VIE架构与跨国诉讼调查（Corporate Registry, VIE & Litigation Teardown）**：
   - 针对未上市独角兽、AI 初创或跨境出海公司，不能只抄新闻通稿里的“某轮融资数亿元”，必须穿透 6 大公开权威源：①境内工商快照与**历史退出股东认缴额**（用 VC 退出前新增注册资本反推天使轮真实稀释比例，并区分「VC 机构数」与「旗下基金主体数」）；②工信部 ICP 备案历史库（区分最大子备案号段与现存在册有效域名数）；③国家网信办大模型/算法备案库（挖出早期内部模型代号）；④境内法院开庭公告（注意区分境内 VIE 登记名义股东与美/港股上市公司股权）；⑤从海外官网 `/privacy-policy` 或 `/terms` 抓出境外签约主体（如特拉华州 Inc.）与海外办公地址；⑥检索美国联邦法院 PACER 诉讼卷宗（`pacermonitor.com`）与 USPTO 商标库（`uspto.report`）。完整检索方法与付费 API 对照表见 `references/corporate-registry-vie-litigation.md`。
8. **品类同类产品横评要打到四层，不能只列国际大牌**：用户问「市面上有哪些类似 X 的产品」时，只交头部三家等于交了半个牌桌。固定四层——① 国际旗舰（定价 / 订阅 / 续航 / 兼容矩阵，逐台列硬参数）② 国产与细分新势力（国行有无官方直售、国行价、售后）③ **白牌与代工链路**（华强北/1688 月出货量、整机 BOM 成本、代工毛利，用来解释价格天花板与为什么仿品打不死正主）④ 跨类新物种（同一形态、不同场景，如语音笔记戒指、宗教刚需戒指），用来找非对称切口而非正面硬拼。再横加**两栏判据**：专利与诉讼清场（ITC 337 禁令、和解与再诉时间线，决定能不能卖欧美）与**开发接口开放度**（API/MCP 有无、是否需商务审批、终端用户停订阅是否直接 403，决定我们的软件能不能接）。前两栏是选型信息，后两栏才决定「自己能不能做、能不能接」。

### Step 4: 用户行为、搜索动作、付费意愿与供应链底牌挖掘 (User Behavior, WTP & Commercial Push)

产品功能（Feature）与市场机会点不由脑暴决定，由**真实用户的搜索动作、掏钱信号、使用断崖与供应链真实毛利**共同决定（详见 `references/user-behavior-and-willingness-to-pay.md`）：

1. **实时搜索动作与购买意图雷达 (`market_intel_tool.py intent`)**：
   - 运行 `python3 $MI_TOOL intent "<核心词/品类词>"`，一键并发拉取 **Google / 百度 / 必应 / YouTube / 淘宝天猫 / Amazon** 6 大平台的实时搜索下拉框联想词（Autocomplete），并自动裂变为「痛点与副作用」「购买与选型意图」「用法与依从性行为」三维矩阵。
   - **洞察逻辑**：搜索框下拉词是全网几十万用户用手指投票出来的最高频真实动作（如搜`甘氨酸镁`直接蹦出`甘氨酸镁副作用睡不着`、`甘氨酸镁一般吃几天停`、`甘氨酸镁怎么吃不伤胃`），直接对应产品最该做的核心功能与获客选题。
2. **八大电商全链路与带货底牌交叉检验 (`market_intel_tool.py ecommerce <词>` + `opencli`)**：
   - 运行 `python3 $MI_TOOL ecommerce "<品类或品牌词>"` 生成 **货架电商 + 兴趣直播电商 + 源头供应链** 8 大阵地采集指令：
   - **货架电商（京东/淘宝/Amazon）**：用 `opencli jd search/item/reviews`、`opencli taobao search/detail/reviews`、`opencli amazon bestsellers/movers-shakers` 提取主力价格带（日均花费锚点）、自营 vs 旗舰店销量结构及 **30–90 天追评原话**。
   - **兴趣与直播带货电商（抖音精选联盟/蝉妈妈/考古加 + 小红书买手种草 + 视频号微信小店）**：
     - 抖音：用 `opencli douyin search/detail/user-videos` 拆解爆款带货视频的前 3 秒黄金钩子与完整口播文案，并配合 `search.py` 检索蝉妈妈/考古加/精选联盟公开数据（看达人带货佣金率 20%–50%、直播间 GMV 构成）；
     - 小红书：用 `opencli xiaohongshu search/note/comments` 筛选「收藏/点赞比 > 0.8」的高转化种草笔记，并统计楼中楼评论区“求链接/怎么买/多少钱”的真实买单密度；
     - 微信视频号（40–60 岁高客单价营养品第一阵地）：借公众号后台 `mp.weixin.qq.com` 的 `/cgi-bin/videosnap` 接口免扫码拉取竞品视频号全量爆款，或用 `opencli weixin search` 追踪爆款动态。
   - **供应链真实 BOM 底价与拼多多白牌底线（1688 + 拼多多）**：用 `opencli 1688 search/item` 查源头代工厂 OEM/ODM 阶梯批发价与起订量（MOQ），结合拼多多百亿补贴价格底线，算出品牌真实毛利倍数（终端价 ÷ 1688 代工价）。
   - **后端弃坑与会员灰产检验（闲鱼 Goofish 照妖镜）**：
     - 首选 `opencli xianyu search "<竞品名> 闲置 未拆封" -f json`；若遇 Chrome 扩展 `attach_failed` / `detached_mid_command`，**严禁跳过闲鱼维度**，立即切换 `search.py --engine serper` 跑 `site:goofish.com "<品类/品牌>"` 与 `site:smzdm.com "闲鱼" "<品牌>" ("闲置" OR "未拆封" OR "代充")` + `web_extract` 抓取闲鱼商品详情页（`goofish.com/item?id=...` 会同时返回主商品与同页 20+ 款同类闲置推荐列表！）。

   - **临床医学与分子机制循证 (`market_intel_tool.py pubmed`)**：
     - 针对健康/营养/医疗/抗衰赛道，运行 `python3 $MI_TOOL pubmed "<英文临床检索式>" -n 8`（底层调用稳定的 Europe PMC REST API `ebi.ac.uk/europepmc/webservices/rest/search`，彻底规避 NCBI E-utilities 间歇性 HTTP 500 故障），批量拉取最新临床研究与 RCT 的 PMID、DOI、年份与摘要，从分子机制（如下丘脑食欲神经肽、皮质醇内脏脂肪轴、围绝经期骨量流失率）解释用户痛点。
3. **两类必抓用户原话（Verbatim Quotes）**：
   - **手工替代方案与挫败点（Workaround & Friction）**：用户在小红书（`opencli xiaohongshu search/comments`）、Reddit（`opencli reddit search/read`）、知乎（`opencli zhihu search`）上晒出的 Excel 表、分装药盒照片或“这几种能不能一起吃”的求助帖 → 直接转化为 AI 产品的自动化功能切口（Feature Wedge）。
   - **迁移触发词（Switching Language）**：专门检索 `"换到了"`、`"弃坑"`、`"switched from"`、`"instead of"`，用 `dbs-jtbd` 拆解推力（旧方案痛点）、拉力（新方案承诺）、焦虑（切换顾虑）与习惯（惰性阻力）。
4. **先审自家产品契约，再做人群合成**：在跑任何外部调研之前，先读自己产品里已写死的文案与字段（课程 JSON 的 `suitableFor` 与课节标题、落地页 Hero、onboarding 题面、SKU 卖点），产出一张「文案病灶对照表」——教科书视角（「升糖与 GI、GL」）要改写为用户当天正在经历的身体场景（「同样是吃饱，为什么有的主食养气色，有的专门长小肚子？」）。人群画像的目的是修正产品，不是产出一份漂亮 PDF；顺序反过来会得到一份跟现有产品对不上的画像。

6. **用户点名平台时的取数阶梯（按序执行，不跳级，也不许换平台顶替）**：
   - ① 先跑 `opencli <site> search`，走本机已登录浏览器的适配器；
   - ② 适配器被登录墙挡住，转 `web_search "site:<域名> <词>"` 取索引摘要——返回的描述里常带主页简介、帖文正文片段与互动数，够做「这个平台上有这类内容」的存在性判断；
   - ③ 知乎另有一条更快的路：答案页与专栏页（`zhihu.com/question/<id>/answer/<id>`、`zhuanlan.zhihu.com/p/<id>`）用 `web_extract` 直取就拿到全文与赞同数，**不需要登录态**，优先用它而不是适配器；
   - ④ 仍拿不到就停手，在报告里单列一行写出页面真实的拦截提示语，并写明缺的是哪类数据（标题/点赞/评论/求链接密度）；

### Step 6: Grounding 核查与浅色一页式 HTML 交付

1. **原文引用台账校验**：
   - 所有引用的招股书数据、研报数字、竞品价格、用户原话，必须登记进 `sources.py` 台账（先 `add <url> --title "..."` 拿 id，再 `quote <id> --text "..." --from evidence.txt` 挂引语——`add` 没有 `--quote` 旗标），并在正文中标注 `[1][2]`。
   - 查不到或被拦截的数据一律如实标注 `not_found` 或 `[未核实推断]`，严禁编造数字或篡改分母（注意核对财报科目分母，如部门收入 vs 集团总收入）。
   - **交付顺序固定**：写完带 `[1][2]` 标记的草稿 → 跑 `sources.py render --replace-in <草稿.md>` 生成标准 `Sources:` 块 → 再跑 `sources.py verify <草稿.md>`，看到 `citations OK` 才算交付。手写 `## Sources` 小标题加项目符号列表**不会被识别**，`verify` 会直接报 `draft cites sources but has no Sources: block`；不要为绕开它去改标记，重跑 render 即可。
   - **中文引语过不了 3 词门槛时扩到整句，绝不手工插空格**：`sources.py quote` 用空白分词判长度（`len(text.split()) < 3` 直接拒），一整句中文只算 1 个 token；而它的空白归一是「把连续空白折叠成一个空格」而非删除，所以你在 `，。` 后插的空格，只要证据原文那里本来没有空格，引语就不再是原文子串，当场报 `not found verbatim`。可靠做法（`scripts/attach_cjk_quote.py` 已实现）：① 用「去掉全部空白」的方式在证据正文里定位短语；② 把命中位置映射回原文索引，向前后取到**整句/整行**边界（`。！？\n`），句子之间本来就有换行与空格，token 数自然够；③ 仍不够就再吞一句，上限 3–4 句 / 600 字符。切片必须对齐句子边界，不要逐字符向外扩——扩进 markdown 图片或链接（`[![Image`、`[文字](url)`）会把链接切成两半，`_MD_LINK_RE` 折叠不了半截链接，同样报 `not found verbatim`。
   - **调 `attach_cjk_quote.py` 时可以传 `--ledger`，但不要自己把它拼进 `sources.py` 的命令**：`sources.py` 的 `--ledger` 只能出现在子命令之前（`sources.py --ledger X quote 3 …`），写在 `quote` 后面会被 argparse 判 `unrecognized arguments: --ledger`。逐条挂引语的批处理里更稳的写法是：先 `attach_cjk_quote.py --id N --from ev.txt --dry "定位短语"` 取回 `SPAN:` 整句，再自己按正确顺序发 `sources.py --ledger X quote N --text "<span>" --from ev.txt`，这样能捕获并逐条记录失败，不会一条被拒就中断整批。
   - **抓取跨零点会把证据落到两个日期目录**：`grounding.py fetch` 按运行当天写 `~/HermesWork/evidence/<date>/`，长会话越过零点后再抓页面，文件就分在两处。构建台账前按 mtime 把当天与前一天的目录一起收（`find ~/HermesWork/evidence -name '*.txt' -mtime -1`），别只读单一 `--date`；漏读的表现是某些来源「挂不上引语」，而不是脚本报错。
2. **视觉与文档交付标准（金字塔「总—分—总」三段式论证结构铁律）**：
   - 生成一份 Markdown 完整存档 + 一份**浅色简洁、一页到底的独立 HTML 调研报告**（白底/浅灰卡片、清晰数据表格、高对比度结论框、可点击原文引用链接，拒绝深色复杂仪表盘）。
   - **HTML 从台账机械装配，不要手敲引用区**：直接读 `--ledger` 指定的那个 `ledger.json` 里的 `sources` 数组，为每条生成 `<div id="ref-{id}">` 锚点块（标题 + URL + 已挂的逐字引语），正文里的 `[n]` 一律写成 `<a class="cite" href="#ref-n">[n]</a>`。两处编号同源于台账，正文与引用区才不会漂移；手敲引用区则必然与 `verify` 的台账对不上。骨架直接用 `templates/report-html.html`（浅色 CSS 变量、KPI 卡、结论框、数据表、引用台账块均已备好，复制后替换内容）。
   - **装配完先跑锚点闭合断言，再打印/交付**：`set(正文 href="#ref-n") == set(str(s["id"]) for s in ledger["sources"])`，两侧差集任一非空就停（dangling = 正文引了台账里没有的号，orphan = 台账里有号但正文没引）。同时扫一遍 `{{` 占位残留。这类错误肉眼扫 400 多个引标根本扫不出来，断言是秒级的。
   - **成品 HTML/PDF 由构建脚本生成时，一切文案修订改脚本里的字符串常量再重建**：手改产出的 HTML，下次重建即被覆盖，还会留下与 PDF 不一致的双版本。脚本化替换每处先断言命中（`assert old in s` 或比对 `count`），重建后 `search_files` 搜一遍新措辞；交付目录只留成稿 HTML、PDF、构建脚本与台账，中间态 `_print_paginated_*.html` 用完即删。
   - **一页到底、不需要页码与目录的报告不要套分页骨架**：直接用无头 Chrome 导 PDF——`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf=out.pdf file://<abs.html>`，配合模板内置的 `@media print`（A4 页边距、卡片去壳、表格与引用块不跨页）。导出前先 `--screenshot=preview.png --window-size=1200,2400` 出图，用 `vision_analyze` 看一眼表格有没有溢出——比导完 PDF 再发现快一轮。
   - **要同时交 PDF 分页版时不要另起一套页数组**：先按 `pdf-generation-fallbacks` §0d 把同一份 Markdown 自动装页（跨技能骨架 `~/.hermes/skills/document-processing/pdf-generation-fallbacks/templates/build_paginated_report.py`），页数与目录页码都从那个页数组反算，HTML 与 PDF 的章节顺序才一致。
   - **报告行文结构严禁按“我先抓了淘宝、又抓了B站、又抓了招聘”的工具流水账罗列！必须严格采用「先给核心结论 → 按核心命题逐个拿多源数据交叉论证 → 最后收束总结与行动底线」的金字塔结构**：
     1. **开篇：核心结论先行**：开篇第一屏直接给出 **3–4 条明确的商业判断**（如：结论 1 我们的产品当前错在哪；结论 2 最精准付费人群是谁、客单价锚点在哪；结论 3 商业闭环怎么走必死、怎么走必通；结论 4 最佳增量截流切口与红线是什么），每条结论配一句话核心证据摘要与 4 个顶层 KPI 数字卡片。
     2. **逐个核心命题的跨源立体论证**：把前面给出的 N 条核心结论逐个展开成独立小节（小节标题就是那句判断本身，不写「论证一」这类编号套话）。在每一节内部，按 **「本节子结论 → 多维一手证据交叉举证（搜索动作 + 电商真实成交/差评 + 1688 BOM 底价/闲鱼弃坑 + 巨头财报/招聘 JD 底牌 + 临床文献/用户原话）→ 本节推导出的商业/产品铁律」** 闭环展开。让所有抓取到的数据服务于论证观点，而不是把数据按平台堆砌成仓库。
     3. **战略收束总结、单位经济总账与行动决策清单**：在全文末尾（Sources 台账之前），用一张**「全局战略对照总表 + 1,000 人池单位经济盈亏平衡账 + 3 条立即可拍板的 Do / Don't 决策底线」**做强力收尾，让决策者看完最后一段即可直接拍板。
     **分区标签与「自我标榜式元说明」绝不许印进成品**：
     - 金字塔逻辑要保留，但「第一部分【总：核心结论先行】」「论证一」「PART 1 · EXECUTIVE VERDICT」这类大纲骨架词严禁写进页眉、大标题、目录或 badge；
     - **严禁把用户的排版/文风指令当成封面标语或章节前缀印在报告里**！诸如 `《晚点 LatePost》商业深度特稿文风 · 先产品后商业 · 零门槛概念白话拆解`、`（共 38 页舒适排版）`、`白话概念扫盲：`、`通俗解读：`、`机器核验通过` 这类向用户表功的“元叙事（Meta-commentary）”一律禁止出现在成品标题、导语和目录中。好的文风和清晰的结构靠正文自己体现，不靠在封面上贴标签。信任类角标同样算元叙事：`Grounding：N 项来源已核验`、`引用 N 条一手数据`、`本报告由 AI 生成` 都不许出现在页眉、导语或 tag 行——核验结果写在 Sources 台账和正文证据里，读者自己能看见。

   - **公司调研的章节顺序：产品在前，资本与商业在后**。决策者打开报告第一件事是判断「这东西我该不该用」。融资表、估值倍数、股权穿透放前面，他读到第三页还不知道产品长什么样，就会要求整篇重排，而重排牵动页码、目录、PDF 分页验收全套。默认顺序：产品矩阵与工作流拆解 → 工序横评 → 公司沿革与股权 → 融资与估值 → 风险与诉讼 → 收束。
   - **写给完全没有行业背景的人（「晚点」体）**：深度不等于黑话密度。`LoRA`、`ComfyUI`、`MCoT`、`FOV`、`Breakage`、`VIE 拆红筹` 这类词第一次出现时，必须紧跟一句大白话锚定（「LoRA：给通用模型加一层几十 MB 的小补丁，教它认一件特定的人或物，成本从几万美元降到几十美元」），再讲它在商业上意味着什么。判据：把任意一段单独发给一个不写代码、不看融资新闻的朋友，他能说出「这家公司靠什么挣钱、卡在哪」，才算合格。术语堆砌换回来的是「看不懂、重写」。

### Step 7: 交付前独立审计（第二模型交叉核查）

定稿前（`citations OK` 之后、把成品递给用户之前）派一轮独立审计。写报告的模型看不见自己的盲区，而用户迟早会问「有没有认真核实过」，那时返工成本是整套重排。

- **换模型家族**：本地 magpie 网关 `http://127.0.0.1:3425/v1/chat/completions`（`Authorization: Bearer magpie`、`User-Agent: hermes-agent`）提供 `cursor/grok-4.7@500k`（备用 `cursor/grok-4.6`），适合当外部审计员；先 `GET /v1/models` 确认 id 存在再发请求。
- **`urllib` 必须显式禁代理**：本机开着代理客户端时，`HTTP(S)_PROXY`/`ALL_PROXY` 会把发往 `127.0.0.1` 的请求先交给代理直到 socket 超时，报错永远落在 `socket.readline`，看起来像「网关慢」。用 `open = urllib.request.build_opener(urllib.request.ProxyHandler({}))`，再 `open(req, timeout=35)`。
- **输入是「报告逐页文本 + 该页段实际引用到的证据原文」**，不是整篇报告 + 全量台账。请求塞到 1 万字符以上会打穿几十秒到分钟级超时；每段 3–8 页、只附该段出现的 `[n]` 对应证据，反而审得更准。
- **五项必查**：数字/金额/比例/案号是否与原文一致、`[n]` 是否错标漏标、无背景读者能否读懂、前后是否自相矛盾、逐页修改建议。
- **子 agent 自报「审计完成」不算完成**：先确认 `audit_part*.md` 已落盘且非空，再按条目改报告并升版本号；数字类问题要回改证据台账，只改正文会让下一轮 `verify` 再次漂移。
- **一次一段、顺序发、每段落盘**：多线程并发流式请求会一起撞 300s 上限，内核被杀时连已完成的那段内存结果也一起丢。
- **审计员报「证据未覆盖」时先回源 grep**：一半以上是你自己喂进去的截断造成的假问题（节点文本砍到前 30 行、JSON 只剩 label）；命中了是裁剪的锅，没命中才是正文编了。
- **审计报「引语挂错源」时补源，不要删句**：机制解释段的内容可能真实存在，只是出自另一篇文章（初轮搜索见过 ≠ 该源含此句）。回源确认原文后把它登记为新的台账源并挂引语；直接删掉会丢掉有效论证，留着不改则是一处硬伤。

切段尺寸、prompt 模板与并行方式见 `references/independent-audit-pass.md`。

## Constraints & Pitfalls

- **严禁把招股书/财报的“行业总盘子”当成“可获得市场”**：招股书里的沙利文报告往往为了帮企业讲故事而把 TAM 划得极大；必须对照财报正文里前五大厂商真实营收之和来交叉核验。
- **财务分母铁律**：转述财报百分比（如“线上渠道占 70%”、“复购率 60%”）时，必须写清分母口径（是占自营收入还是总 GMV？是 90 天复购还是年复购？）。
- **调研词根必须先跑工具再下结论**：写“用户在搜 X”之前必须已实际执行 `market_intel_tool.py intent`（或等价的 autocomplete 直连），并逐字摘录下拉词；凭直觉列举搜索词等于编造一手数据，直接违反 Grounding 红线。
- **把 `opencli` 命令写进文档前先跑 `opencli <site> --help`**：适配器签名是**位置参数**（`opencli jd search "词" -f json`、`opencli taobao detail <id>`），不是 `--keyword` / `--url` / `--query` 这类旗标；按记忆或旧文档写旗标，命令当场报参数错误，而同事拿到 handoff 后会在自己的环境里重复踩一次。同一站点不同子命令的入参形态也不一致（`search <query>` vs `detail <id>` vs `bestsellers <url|node>`），逐个核对。
- **技能改动必须同批同步到全部投递目标**：本机 `~/.hermes/skills/`、同事环境 `~/.config/alma/skills/`、`marovole-Superpowers` 仓库的 `skills/research/<name>/` 与 `docs/handoff-*.md`。handoff 文档里内嵌了 `market_intel_tool.py` 的**字面副本**，只改技能里的脚本而不改 handoff，等于给同事发一份带旧代码的安装包；脚本新增子命令时，handoff 的 argparse 段、Step 说明与验收脚本三处要一起改。
- **中文 seed 不要只跑 Google**：Google 的中文电商/消费类长尾覆盖明显弱于百度、淘宝，单平台取词会系统性漏掉“哪个牌子/多少钱/怎么吃”这类付费与依从性意图；六个平台（Google/百度/必应/淘宝/Amazon/YouTube）至少跑中文三源 + 英文两源。
- **做人群与闭环调研时，别先写行业总盘子**：先读自家产品契约拿病灶，再跑搜索动作拿 ICP，最后才用四象标杆与单位经济表论证闭环。开篇就上「XX 行业 3000 亿」的写法，读者拿不到任何可执行结论，也不符合本技能要防的表演式调研。
- **别把「内容/课程本身就是产品」当成结论**：高价内容类业务单靠卖课/卖会员普遍被免费内容击穿（分部收入下滑、单用户 ARPU 低个位数），必须把内容定位成前端信任钩子，利润落在实物/耗材/订阅与复评调方上。写闭环时若利润仍只来自课程收入，方案要重做。
  **可执行的证明方法（比访谈硬）**：在同一平台、同一人群词下横向搜五种交付形态——纯录播课 / 静态食谱资料 / 同名图书 / 1v1 定制计划+实时看餐答疑 / 功效型实物（补剂或低 GI 主食替换），记录「单价 × 真实付款人数」。量级落差通常跨 4 个数量级（个位数付款 → 数百单 → 千至十万级），这条曲线就是「内容不是产品」的判决书。表格模板与三条配套铁律见 `references/user-behavior-and-willingness-to-pay.md` 第五节。
- **用户说「更深、更广、要我们自己抓的数据」时，先交数据实证，不交落地方案**：这类追加指令的真实含义是「你上一轮引的是一手平台之外的二手文章，我要平台原始数据」。正确响应是回淘宝/1688/Amazon/B站/Reddit 抓交易笔数、评价原话与代工报价，产出一份纯实证报告（谁在付钱、付多少、原话怎么说、毛利几倍），把方案留到对方明确要求后再给。把「调研」和「方案」分成两次交付，是这一轮指令的验收条件。
- **「原文引用」不等于「一手抓取」**：引用第三方专栏、媒体测评、营养师文章只是二手证据，哪怕引语逐字准确也不能单独支撑人群画像。人群画像、付费意愿、痛点排序这三类结论必须落在自己抓的平台原始记录上（付款人数、买家评价原文、代工厂报价、高赞评论区原话）；二手文章只能用来解释一手数据背后的机制（如「肌肉每十年流失 3–8%」这类生理学解释），不能用来定义人群。
- **用户点名的平台拿不到样本时，缺口要写在报告里，不许用另一个平台的证据顶替它的结论**：用户说要覆盖哪几个平台，就是验收条件的一部分。某站被登录墙/验证码挡住，就在平台对照表里如实写「本次没拿到什么 + 页面原文拦截提示」，而不是拿同赛道另一个平台的热度代替。用「某报说该平台讨论很热」充数更糟——那是媒体的观察，不是你的样本。
- **排行榜前排的「独立第三方测评」可能是批量伪造的学术背书，先验 DOI 再引用**：一组互相引用的测评站（十余个子域互相背书、共用「XX-2026-01 六款 App 独立验证」式研究编号）可能整篇虚构作者团队与 Zenodo DOI，用来把某款产品的误差写成「±1.1%」。三条判据：① 该数字若比同任务上 Nature/Google/CVPR 正刊论文的实测（十余个百分点量级）好一个数量级，默认不可信；② 把 DOI 当 URL 打开，404 或指向无关条目即判伪造；③ 看这些站是否只在这组站内互引、且都指向同一款产品。真实第三方实测（NIH/大学医院/受控喂养称重）会写明样本量、称重精度与被测版本，三者缺一即降级为厂商自述。
- **精度数字必须绑定「指标 + 数据集 + 样本量」才能进同一张表**：厂商 FAQ 自报「~15% 热量误差」，在第三方测试集上可能测出 25%–35%；论文的 `MAE 45g` 与榜单的 `MAPE 15%` 也不是一回事（克重绝对误差 vs 相对百分比、单菜 vs 单餐、是否含隐形油盐）。每格缺任一项都不能并列排行，否则横评表看起来专业、实际不可比。
- **HTML 台账装配脚本不要塞进 `python3 -c`**：装配逻辑要嵌套引号、f-string 里再插引号或反斜杠，shell 单引号 heredoc 会当场报 `SyntaxError: f-string expression part cannot include a backslash`，而错误位置常指向看起来无关的行。用 `write_file` 落一个 `build_html.py` 到 scratch 目录再 `python3` 跑它；每改一处重跑一次，比在 shell 里转义十几层稳。**改版重建同名装配脚本前先把整篇读完**：`write_file` 对「本任务没读过全文」的文件拒绝覆盖，而上一轮只读过局部片段的脚本正好落在这个网里，被挡一次就白一个来回；要么 `read_file` 按 offset 读到底，要么直接新建 `build_html_v<新版本>.py`。
- **模板里的 CSS 变量名不许猜**：`var(--muted)` 与 `var(--subtle)` 一字之差，模板未定义的那个不报错、文字静默回落到浏览器默认色，截图里几乎看不出来。复用模板前先看它 `</style>` 前那两个块定义了哪些变量，新增样式只引用已存在的名字。
- **导出 PDF 后用文本回读做最后一道排版检查**：`pdfinfo` 看页数与页面尺寸（A4 应为 `594.96 x 841.92 pts`），`pdftotext -layout` 落一份文本逐段读——表格横向截断表现为某列文字缺失或整行串位，短行内代码（`glm-5.4[1m]` 这类）会在窄列里被折成两行，出现就给该处 `white-space: nowrap` 或缩短文案。这比逐页截图快，还能顺带确认打印样式没把正文刷成浅灰。
- **架构机制与实测遥测之间没有官方技术报告时，不做因果归因**：一次发布里同时给出「新架构」与「实测变慢 / 烧 token 翻倍」两个事实时，把后者写成前者的必然结果是编造。机制段引技术说明或业绩会原话并讲清它省的是存储与读取带宽，遥测段引实测记录，末尾明写一句「尚无报告说明两者关系」。
- **用 `build_report.py` 这类脚本改已写好的正文时，每次替换都要断言命中**：`s.replace(old, new)` 遇到一个空格、引标或标点差异就静默不变，脚本照样打印「patched」、HTML 照样重新生成，旧句子原样发出去，只有回读成品才发现根本没改上。replace 前 `assert old in s`（多处替换就对 `count`），重建后用 `search_files` 搜一遍新措辞，别拿字符串长度或「已写入」提示当成功信号。**改的是表格单元格时，还要断言该行 `|` 分隔的格数与表头一致**：多写或少写一格，markdown 会静默吞掉/错位整行，表格看起来还在、内容已经串到别的列，肉眼扫根本发现不了。
- **厂商自报的经营指标必须写成「公司自述 + 对照基准出处 + 样本量」**：留存率（如「6 个月 68%，其引用的行业基准 46%」）、减重百分比、订阅转化率这类数字，几乎全部来自公司自己发布的白皮书或博客。照抄成行业事实，等于替厂商写通稿；正确写法是把口径摆在数字旁边，让读者自己判断可信度。
- **服务类订阅的价钱要拆成多层记录，不能只抄一个数**：处方药/商品费、平台会员费、营养师按次或包月、送餐物流、App 增值，五层各有各的价，标杆页普遍把药费排除在会员费之外（会员 39–199 美元/月，药另计 25–449 美元/月）。同时记清首月促销价 vs 续费档位、年付折算月价，以及「不保证覆盖/不保证有货」这类免责句——免责句决定这个价到底能不能交付。
- **`radar -c` 每次只传一家竞品**：生成器会把 `-c` 的整串用双引号包进检索式，`-c "A OR B"` 会变成 `("A OR B")` 这个单一字面短语，看起来像 OR 实际不生效。多竞品就分行调用多次 `radar`，或把竞品名去掉空格后单传。
- **公司调研里“产品力”是必答项，不能等用户追问**：一份只有融资历程、估值倍数、ARR 与赛道格局的报告，在决策者眼里是半成品——他要拿它判断“这东西我该不该用/该不该投”。写完资本部分就收工，下一轮必然收到“产品也要深入调研并合并进报告”的返工指令，且要重跑 HTML+PDF 全套。默认在首版就给出产品拆解章节（工作流解剖 + 独门功能 + 实测硬伤 + 工序横评）。
- **功能清单式对比没有信息量，横评维度必须落在生产工序上**：列“支持 4K / 支持多模型 / 支持导出”这种表，任何两家都能勾满。真正决定采购的是同一道工序上的返工成本（单镜改一处会不会崩全局）与工程出口（能不能直导剪映草稿/PR 工程）。
- **厂商 features 页的“支持 X”不等于可用**：常见形态是 beta、灰度、需自备外部 Agent 与 access key、或仅限特定订阅档。把“支持”写进报告前，必须用第三方上机教程或官方文档确认前置条件与真实操作路径，否则等于替厂商写通稿。
- **写优点必须同时写它的代价**：每项提效功能后面跟一句代价（25 宫格提效但废片率上升、3D 导演台控构图但抬高上手门槛、Agent 一句话出片但复杂指令常漏做后半截）。只写优点的产品章节不可信，也会被用户当成软文要求重做。
- **在既有报告上追加章节时，只追加不重排**：新引用一律接在 Sources 台账末尾继续编号（`[32]`、`[33]`…），绝不重新编号或插队——正文里已有的 `[n]` 全部靠编号绑定，重排一次整篇引用即失效。追加后必须三处同步：Markdown 正文 + HTML 正文新章节 + HTML 引用台账（含章节标题里的「第 N 章」与「N 项引用」数字）；只改 MD 会交付一份与 HTML 数据不一致的双版本。
- **交付前扫一遍占位符与脱敏残留**：工具输出里含敏感串时会被替换成占位符，若直接粘进报告标题/URL，交付物里就会出现「X 占位符招聘」这种断句。定稿前全文搜一遍双花括号形态的占位标记，命中就把该条标题改写成不含敏感串的表述。
- **引标与锚点用脚本断言，不要肉眼扫**：装配完 HTML 跑 `scripts/verify_report_anchors.py <report.html>`，它同时校验「正文 `[n]`/`[En]` ↔ `id="ref-n"` 闭合」「图片 `src` 都能打开」「无 `{{ }}` 占位残留」，任一不通过 exit 1。同时支持数字引用与 `[E1]` 式证据编号。
- **交付 handoff 文档前，里面每个第三方控制台/领 key 链接都实际打开点一遍**：`serper.dev/api-key` 与 `/api-keys` 一字之差，前者是 404；凭记忆写 slug，同事照着点会卡在第一屏就放弃。同理，文档内嵌的安装脚本要在一台干净环境按原样跑一遍，别只跑自己机器上已经装好的版本。
- **用户给的链接可能是同名不同公司的产品**：下任何技术判断前先核域名、`/terms` 里的法律主体与 App Store seller name，三者对不上就以「你给的文档属于另一家公司」开头纠正；只凭名字相同就把别家的 API/MCP 当成本产品的能力，整份答案作废。
- **网传匿名案例的「行业真伪」与「个案真伪」必须分两栏写**：没有具名主体认领的案例声称（「某大卖用 X 搭了全链路 Agent、100 人研发」），公开渠道查不到就如实标「主体未具名，按匿名访谈处理」，然后分别核：① 行业层——同赛道上市公司季报与投资者关系活动记录表里有没有可量化的 AI 财务归因（营收与净利增速裂口、费用率同比、自研平台名）；② 生态层——该底座在 GitHub 上有没有真实二开发行版与垂直插件。把「行业确实在做」写成「这家确实做了」等于替推主写通稿；反过来因主体查不到就判「没这回事」，会误杀真实趋势。
- **判一个开源 Agent 运行时能不能上生产，看四件事不看 Star 数**：版本阶段声明（是否仍标 Developer Preview、是否声明未过安全审计）、安全记录（有没有已修复版本的未授权 RCE / 沙箱逃逸，还是只有「建议升级」）、供应链（插件投毒与权限披露机制）、控制面缺口（是否必须自建 RBAC / 会话沙箱 / 密钥隔离 / 审计回放）。Star 与插件数是热度证据，不是可用性证据；拿热度下「可上线」结论是这类调研最常见的注水。
- **「接口存在 / 文档在线 / 官方支持」是三个独立事实，不许合并成一句「有 API」**：真实路径 401 配伪造路径 404 才能证路由存在；文档站要用 DoH 查 A 记录，索引里还有摘要不算站点还在；后台登录页还在不等于现在仍发新 key——没注册验证过就写明「未测」。
- **章节序号必须连号，合并/删除章节后当批重排后续标题**：草稿阶段砍掉或合并过一节，成品就会出现「一二四五六」的断号（原本的第三节没了），读者一眼看出返工痕迹。定稿前 `grep -n '^## '` 过一遍序号，重排要与删节在同一次编辑里改完全部后续标题，Markdown 与 HTML 两处一起改。
- **调对方 MCP 工具前先读 server-card 的 `inputSchema`，参数名不可猜**：`nutrient_name` 不是 `nutrient`、`products` 不是 `product_ids_or_slugs`，猜错只回一句 `Missing required arguments`，看起来像对方接口坏了。同一轮顺手试长短两种查询词：`find_products` 传「品牌+品类+剂型」常回 `No products matched`，退到只传品类名才命中——空结果先怀疑自己的 query，不要先写成「他们库里没有这个产品」。
- **标杆 Shopify/DTC 站的全量 SKU 要取 `/products.json`，且在浏览器会话里取**：`curl` 打这类端点常回 HTML 挑战页而非 JSON，`json.loads` 报 `Expecting value: line 1 column 1` 时不要写成「该站没有公开数据」；改成浏览器 `goto_url('<shop>/products.json?limit=30')` → `js('document.body.innerText')` 落盘再解析，一次拿到全部 `handle`/`title`/`body_html` 与 variant 的 `price`/`compare_at_price`，比猜 `/collections/<x>` 可靠且不会因 404 得出「没有套装」的错误结论。读法与套餐机制见 `references/ecosystem-radar-signals.md` 维度 4。
- **竞品队列跑完后必交一张「终局作战图」，不能只交 N 份平行报告**：用户按优先级让一个接一个拆时，每个产品的结论是孤岛，决策者要自己比。收尾报告里给一张横表——每行一个竞品（商业模型与体量 / 最值得抄的一项长板 / 它留给我们的一条空档），再跟一张「把各家长板焊在一起」的行动蓝图与定价/文案底线。这张表是队列调研真正的交付物，平行报告只是它的证据附件。
- **供应商实测评测报告的结论必须挂逐字产物对照，概括性评价会被退回重写**：写完「它擅长日常办公、写长文会编造」这类判词，用户下一句就是「不够清晰易懂，结果要有具体测试案例作对比」。默认首版就按 `references/build-vs-buy-agent-platform.md` 第 6 节交：拍板句＋计数 KPI 卡＋左右对照框＋分组能力表＋附录逐字案例（`❌ 它交出的原文` vs `✅ 我们交出的原文`），案例里保留它的底层报错、危险建议与字数虚报倍数——这些才是采购决策依据。
- **评测报告不按测试轮次叙事**：禁止「第一轮/第二轮修正了什么」的时间线写法，测试过程按决策视角合并成结论，轮次只留内部台账；同一套系统的「问答态诚实 / 创作态瞎编」这类反差要单独成栏并给出两种用法，不要拉平成一个总分。
- **写综述类报告前，先搜一遍本技能 references/ 里有没有现成的报告形状**：`build-vs-buy-agent-platform.md`、`product-teardown-playbook.md`、`hype-claim-verification.md` 各自规定了不同问题的收束结构，开写前选对骨架比写完再重排便宜一整轮。
- **单位经济账必须把变动成本与固定成本分开，否则盈亏平衡点一定算错**：随客户数线性增长的项（AI 推理算力、履约、支付通道、退换货）是变动成本，只能从边际贡献里扣；把它们并进固定成本再相除，平衡点会虚高一截（同一套账，混算 615 名、正确拆算 573 名）。固定用瀑布式逐层写：`GMV → 商品毛利 → 减营养师佣金 → 减履约支付退换 → 平台净留存 → 加软件订阅 → 减变动成本 → 边际贡献 → 减固定成本 → 税前结余`，每一层都标出公式与假设口径，并显式写明「未含库存营运资金、税费与爬坡期亏损」，别用「完全脱离烧钱」这类判词收尾。末尾固定附一张悲观/基准/乐观三档敏感性表（买家数 × 综合毛利率 × 平台留存率），并点名哪个假设才是生死杠杆——通常不是软件定价，而是供应链毛利率与人均复购客户数。
- **分润、抽成、留存比例只允许有一个定义，改一处就要全局对齐**：策略章节写「平台自留 18%–22%」、总账表却按 20% 落数、正文另一处又写 25%–30%，是审计最先抓、读者最先怀疑整份测算的硬伤。定稿前把每个百分比在 Markdown 与 HTML 里各 grep 一遍，确保策略段、总账段、敏感性表三处引用的是同一套数字。**分项计数同理，还要与分母闭合**：写「27 项中 X 命中」时，命中 / 正确拒答 / 未命中三栏必须相加等于分母，而这个结论通常同时出现在 KPI 卡、对比表、结论框、执行摘要与台账引语四五处——心算汇总必然丢项，先回原始命令输出逐条数一遍，再一次性 grep 全改。**台账里的逐字引语不许为了对齐新统计而改写**：它是证据快照，数字变了就重跑命令、把真实输出贴回引语，而不是把引语改成你想让它说的措辞。
- **版本与相关性命名规范**：交付文件必须包含与调研主题/主体强相关的可读命名及版本号（如 `<主题>-深度调研-YYYYMMDD-v1.0.pdf`、`mistral-vs-ollama-ab-20261118-v1.0.pdf`），严禁直接命名为泛化的 `report.*` / `report_v1.0.*`；升级直接升版本号（如 `v1.0` → `v1.1`），严禁使用「终版」「无xx终版」字样。
- **国家统计局年鉴的数据表是图片，别用 curl 硬啃**：核心表（如普查年鉴表 3-1）以 JPG 发布，`curl`/`web_extract`/firecrawl 只能拿到 HTML 壳。用 `vision_analyze` 读原表图片（按「合计=男+女」互验）+ 第三方文本镜像逐组加总 + 学者引用三方互证，落到同一个数才算锚定。路径见 `references/china-official-statistics.md`。
- **人口与宏观口径、时点不可混用**：「生育旺盛期 21—35」（统计局）与「主力育龄妇女 20—35」（泽平/育娲）只差 1 岁但出处不同，引用不可互换；普查时点数、年末数、1% 抽样时点数三者不可混用；年鉴 N 收录 N-1 年数据，写「等年鉴出版」时年份要加 1。
