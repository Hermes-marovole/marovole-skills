# 产品力拆解手册（Product Teardown Playbook）

用于公司调研、竞品分析、供应商选型里的「产品到底怎么样」章节。目标是让读者能判断「这东西我该不该用、该不该投」，而不是拿到一张功能勾选表。

## 1. 证据层级：按可信度从高到低

| 层级 | 证据形态 | 能支撑什么 | 风险 |
| :--- | :--- | :--- | :--- |
| A | 逐帧实操教程（B站/YouTube 长视频、图文步骤） | 真实工作流、每步输入输出、卡点与失败模式 | 教程可能用的是旧版本 |
| B | 第三方上机测评（多产品对比、付费用户长评） | 横向优劣、真实耗时、隐形成本 | 测评者的粉丝滤镜与商单 |
| C | 官方 docs / changelog / 帮助中心 | 功能边界、计费规则、限制条款 | 只写「支持」，不写「在什么条件下不支持」 |
| D | 官方 features / pricing / 宣传页 | 只能当**厂商自述**引用 | beta、灰度、需自备 key、仅限高档订阅 |
| E | 新闻稿、公众号软文、融资通稿 | 只能当事件与时间线 | 产品描述基本是通稿复述 |

铁律：**A/B 才能写「好用/难用」，C/D 只能写「官方声称」**。把 D 层写进正文不加限定，等于替厂商写通稿；用户会把它当软文要求重做。

## 2. 四段式拆解结构

1. **产品矩阵与定位**：有几条产品线、各自服务谁、彼此怎么导流、哪条是现金牛、哪条是获客钩子。一张定位图 + 一句话说清「为什么一家公司要做三个产品」。
2. **按真实生产工序拆工作流**：不要按 UI 菜单列功能，按用户真正做一件事的顺序排（选题 → 脚本 → 分镜 → 出图 → 出视频 → 配音 → 字幕 → 发布）。每道工序写三件事：输入什么、输出什么、**这一步最常怎么失败**。失败模式才是采购决策依据。
3. **独门功能 vs 通用能力**：把「只有它有」和「大家都有的封装」分开写。独门功能要给出「为什么竞争对手短期抄不了」（数据飞轮、独家模型配额、工程细节），否则只是营销点。
4. **实测硬伤、定价陷阱与适用边界**：每条优点后面必须跟一句代价。

## 3. 写作纪律

- **写优点必须同时写代价**：25 宫格提效但废片率上升、3D 导演台能控构图但抬高上手门槛、Agent 一句话出片但复杂指令常漏做后半截。只写优点的产品章节不可信。
- **积分制必须换算成钱**：用户看不懂「消耗 30 积分」。把各档会员价 ÷ 每月积分 × 单次生成消耗，换算成「一条 5 秒视频约 X 元」，再对比竞品同工序价格。这是全篇最容易被验证也最容易被质疑的数字。
- **区分「做不到」和「要加钱才能做」**：很多「短板」其实是档位限制，写错会被付费用户打脸。
- **每个结论标注证据层级**（如「据第三方上机测试」「据官方文档」），让读者知道该信几分。

## 4. 横评：按工序，不按功能清单

功能清单式对比（支持 4K / 支持多模型 / 支持导出）没有信息量，任何两家都能勾满。横评表必须以**生产工序为行**、以**产品为列**，单元格写该工序上的真实体验与返工成本：

| 行（工序） | 要看什么 |
| :--- | :--- |
| 角色/主体一致性 | 换镜后人物脸、服装、场景是否崩；有无参考图锁定 |
| 单镜可控性 | 改一处会不会崩全局；能否只重绘局部 |
| 批量与并发 | 一次能出几条；排队时长；失败是否退积分 |
| 工程出口 | 能否直导剪映草稿 / PR / AE 工程，还是只能导 mp4 |
| 配音与口型 | 是否自带 TTS、多语种、口型同步质量 |
| 字幕与合规 | 自动字幕准确率、敏感词检测、平台尺寸预设 |
| 协作与版本 | 多人协作、素材库、历史版本回滚 |
| 成本曲线 | 单条成本随分辨率/时长/重试次数的增长斜率 |

输出成「每道工序谁最强 + 差多少」，比一排勾号有用得多。

## 5. 真实用户口碑怎么读

- **评分站**（Trustpilot / G2 / App Store / 应用宝）先看分布不看均分：1 星占比高但均分不低，说明产品有两极分化人群，要拆出「谁满意、谁暴怒」。
- **差评聚类**：把 1–3 星按主题聚类（扣费/退订/生成质量/排队/客服），每类摘 1–2 句逐字原话。原话比百分比有说服力。
- **注意样本偏差**：海外评分站的用户构成与国内主力用户不是同一批人，海外 1.5 分不能直接推出国内产品差；反过来国内好评也不能证明出海能成。
- **弃坑信号**：闲鱼/二手平台的「闲置未拆封」「代充」是付费意愿的真实地板价，比任何问卷都硬。

## 6. 常见翻车点

- 把厂商的「一站式」当事实：一站式通常意味着每一环都只是及格，逐工序拆开就会暴露。
- 只看官网定价页：真实成本在积分消耗率、失败是否退积分、并发是否需要更高档位，这三处官网通常不写。
- 把「用户量」当产品力：注册用户 ≠ 月活 ≠ 付费；三个数分开写，拿不到就标未披露。
- 只写优点：交付后会被要求「重写，别像软文」，返工成本是整章重做。
- 用功能数量做结论：功能多通常是维护负担，不是体验优势。
