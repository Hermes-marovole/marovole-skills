# 模型 / 产品发布与「开源」声明核验

适用于厂商开大会「连发 N 款」、通稿写「全面开源」「可本地部署」「行业第一」，用户接着问「这东西能用吗 / 哪里能调 / 要不要自己部署」这一整类调研。核心是**把宣传语翻译成可交付物清单**：通稿里的一个「开源」可以同时指权重、代码、评测数据集、模型服务四件事，整个家族给一个总判决必然失真。

## 1. 开源声明按四档落表，逐仓对文件

| 档位 | 判定依据（只认仓库里能 `from_pretrained` / 能 clone 的东西） |
| :--- | :--- |
| 完整权重 | HF/ModelScope 有 safetensors + config，无门控，另有量化版/推理镜像 |
| 仅轻量组件 | 只放出编码器、小尺寸或 embedding，主模型不给 |
| 仅代码 + 评测数据 | 代码与 benchmark 数据齐全，权重留在自家 API 后面 |
| 全闭源 | 只有 App 内体验或控制台入口，无仓库无模型卡 |

逐款一行，写清「实际放出的资产」与「与宣传口径的落差」两列。落差列是最有价值的一列：媒体标题说笔记本可跑、模型卡说 4×141GB；宣传说 150 种疾病预测、模型卡写 `task-specific prediction heads are not included`。

## 2. 「可本地部署」回模型卡查 serving 硬件配方

媒体转述的部署门槛几乎总是错的。模型卡的 SGLang/vLLM 配方（TP4 4×141GB / TP8 8×80GB / 8×H200）才是判据，它决定这模型是「医院的私有化选项」还是「个人可跑」。把配方原文抄进报告，并直接算出隐含成本区间。

## 3. 权重没开 → 评估整体下沉到托管层

托管可用性按三态查（接口存在 / 文档在线 / 官方支持，方法见 `integration-surface-audit.md`），本类发布另加三条专用检查：

- **区域双站**：国内站与海外站各有一套 BASE_URL 与 model id，吞吐与价格常差一个量级（同一模型海外站吞吐可能只有国内站 1/4）。报告分列两站，别把一站的实测当全球性能。
- **免费期**：若同平台另一款模型已公告「某日某时结束免费」，就把本款也按「限免、随时转收费」处理并写进风险栏。
- **价格锚点**：正式价未公布时，用**同底座、同参数量、已上架的兄弟模型**公开牌价当锚（输入/输出分别列），比空写「价格待定」有用得多。
- **第三方平台上架状态**：发布 1–2 天内 OpenRouter / 硅基流动 / 百炼 / Together 基本都没有，明确写「截至某日仅官方双站」，避免用户按已上架去找。

## 4. 榜单要看覆盖矩阵，不只看名次

自建或联署榜单（多机构联合发布的那类）先找它的**评估矩阵**：通常是「角色 × 能力」的网格。核对被测模型实际覆盖了几格、哪几格是空的——常见形态是 9 格里只测 3 格，且「面向普通用户 / 患者」那一整列全空。结论句必须写成「总榜第几 / 开源组第几 / 覆盖了哪几格」，把「第 1」拆开写；单任务估价（$x/task）与综合分一起给，方便判断性价比站位。

## 5. 基准表复原纪律

社媒只挑一项最好看的分数传播。回模型卡（或技术报告）的评测图逐项读全表，按**强项 / 持平 / 明显落后**三档归纳，并给出对照的闭源旗舰型号与同级开源对手。两条硬规矩：

- 强项一侧必须配一行代价或弱项——只写优点的模型章节等同软文。
- 精度/得分数字必须绑定「指标 + 数据集 + 样本量/口径」才能进同一张表；厂商自报的 F1、自建中文测评集分数要写明口径与版本。

## 6. 收束形状：不自建前提下的三路线矩阵

用户问「哪里能调」的下一句通常是「要不要自己部署」。收尾固定给三条路线横表（验证周期 + 隐性成本两列不能省）：

1. **官方托管 API**（首选）：改 `base_url` 即可，周期 1–2 天；风险是免费期结束的单价、限流、以及国内应用商店上架所需的算法备案资质。
2. **复用开源数据与轻量组件**：与其自建主模型，不如把对方开源的评测集（安全/合规/伦理类样本）并入自家护栏回归，编码器类轻量组件先本地试。周期 3–5 天。
3. **自建集群**：只在私有化/数据不出域/调用量极大时考虑，把 GPU 门槛写死，周期按周起。

最后落「本周 DO / DON'T」：DO 是拿自家真实样本（业务现场照片、报告、长文）做几十到上百条盲测 + 复用对方开源测试集；DON'T 是不轻信二手部署门槛、不把只给编码器的组件当成品、严守模型卡写的「不得用于独立诊断/处方」红线。
