# 竞品 App 实机拆解（安卓模拟器 + 无障碍树）

网页调研拿不到 App 内的东西：付费墙怎么叠、默认选中哪一档、售前方案和进首页后的实际预算差多少、AI 助手怎么答补剂问题。这些只在装机后的一次真实走查里出现。本手册是「装 APK → 走完关键路径 → 落证据台账 → 写横评」的作业流程，配 `market-intelligence` 的 Step 3「产品力拆解」使用。

## 模拟器选型

| 目标 App | 选哪个 | 为什么 |
| :--- | :--- | :--- |
| 国内 App（有无 GMS 都能跑、带厂商风控/加固） | **MuMuPlayer Pro**（网易，Apple Silicon 原生） | 国内 App 的检测常看机型与 GMS 缺失，MuMu 伪装三星真机后登录/注册一般能过；Google 原生 AVD 在这些 App 上容易卡在启动或登录 |
| 海外 SaaS / GMS 依赖 App | Google 原生 `emulator` AVD（`arm64-v8a`） | 免费、可无头后台跑、GMS 完整；对国内加固包无优势 |

装 MuMu 后 ADB 默认在 `127.0.0.1:16384`，且 `adb` / `emulator` 通常没进 `PATH`——找不到时用 Android SDK 的绝对路径调，不要判定「没装」。

## 作业流程

### 0. 连通与驱动

```bash
adb connect 127.0.0.1:16384
adb devices -l                       # 看到 device 才算通
agent-device --help                  # 先读命令表，不要凭记忆写子命令
```

抓一份当前屏，确认工具链能出图：

- **截图**落盘为 `NN_<scene>.png`（保留原始分辨率，像素取证全靠它）；
- **无障碍节点树**同时落盘为同名 `.json`（含 `identifier` / `rect` / `label`），另出一份 `.txt` 人读版。

`.json` 是引用「逐字原文」和坐标的唯一依据，截图只能当视觉佐证。

### 1. 人肉关卡先让用户过

隐私协议勾选、手机号/微信扫码登录、以及首轮验证码，一律让用户自己点一次：`adb` 输入密码/验证码既违反凭证红线，也容易被风控标记。用户登录完再接管，之后同一会话内的页面都可以自动走。

### 2. 走关键路径，一屏一落盘

顺序按用户真实使用排，不要按功能菜单排。健康/消费类 App 的固定路线：

建档评测（逐题抓题面 + 默认值 + 实时反馈文案）→ 方案/结果页（含底部小字角注）→ 付费墙 → 关闭/返回后的实际落点 → 首页真实数据 → 核心工具（记一笔）→ AI 助手问答 → 每个底栏 Tab 首屏 → 商城/定价页。

每屏做完立刻落 `NN_<scene>.png` + `.txt/.json`，编号从 `01` 连续，事后靠编号写 `[E1]…[En]` 台账。

### 3. 像素取证三件套

界面上的「小气」「诱导」「不显眼」必须量出来，不能只写形容词：

1. **热区换 dp**：`dp = px ÷ (dpi / 160)`。例如 `118px` @ `540dpi` ≈ `35dp`，低于安卓无障碍 `48dp` 下限才写「小于标准热区」。换算写错（算成 21dp）会被一眼拆穿。
2. **叠压算重叠像素**：两个节点的 `rect` y 区间相减，写「主按钮覆盖月卡顶部 31px」，不写「拦腰截断」。
3. **默认选中态**：付费墙哪一档高亮、哪个按钮文字不写金额（如只写「下一步」），都要点名，这是转化设计的关键证据。

### 4. 横评按工序，不按功能清单

用一张「用户完成一次该任务的六道工序」表收束，每道工序一行：建档分型 → 方案生成 → 日常记录 → 专业指导 → 复评调方 → 商业承接。每格写「实机表现（带 `[E*]`）｜ 失败模式与代价 ｜ 我们的破局切口」。功能清单式对比任何两家都能勾满，没有决策价值。

### 5. 交付

- Markdown 存档 + 浅色一页式 HTML（结构、CSS、KPI 卡、锚点台账直接用 `templates/report-html.html`）；
- 正文 `[En]` 与文末 `id="ref-En"` 锚点必须一一对应，图片 `src` 必须都能打开——装配完跑 `scripts/verify_report_anchors.py`，不要肉眼扫；
- 再按 `references/independent-audit-pass.md` 派一轮异构模型审计，改完升版本号。

## 健康/消费类 App 的固定观察点

- **售前售后两套账**：评测结果页给的热量/方案，进首页后是否变；两处数字都抄原文。
- **隐藏角注**：方案页和付费墙底部的小字常写着会员数、减重均值、统计口径（「仅统计整月在期且主动记录的用户」），这是最便宜的一手经营数据。
- **付费墙三件套**：默认选中档位、主按钮是否隐去金额、关闭键尺寸与位置；点关闭后是否再弹挽留、返回后落在哪个 Tab（强跳商城 = 洗流量）。
- **功能阉割对比**：「今天」有的入口「明天」还有没有；同一数据换个日期同屏对比，是核实付费墙/降级最干净的一招。
- **AI 助手的三个失分点**：不追问关键剂量口径（元素量 vs 化合物量）、给出违反药理常识的服用建议（空腹高锌、镁锌同服竞争吸收）、答完不落档案无回访。
- **适应症越界**：处方药/医疗服务对非适应症人群（如 BMI 正常却被推减重药）是否零门槛展示；药盒打码而价格明标是常见规避手法。
- **社区首屏人群错位**：向 40–60 岁用户推 BMI<18.5 的学生党内容，是内容分发完全没有人群约束的证据。

## 坑

- **别拿截图当唯一证据**：截图里的文案不可逐字核对、坐标不可复算。凡是要写「原文/逐字/完整」，必须来自 `.json` 的 `label`。
- **APK 走官方/应用宝 CDN 直链**，`adb install -r <apk>`；下载中断的后台进程要清掉，残留的半个包会让下一次安装报 `INSTALL_FAILED_INVALID_APK`。
- **不要在同一模拟器上来回切换账号做 A/B**：登录态、风控指纹、缓存都会串，两次实验的结论不可比。一个账号走完一条路径，换问题就换会话不要换身份。
- **报告里的「实测未见 X」不要写成「没有 X」**：一次走查只能证明你没看到，不能证明不存在。
