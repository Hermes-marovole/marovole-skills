# 把外部创作者方法论吸收进自有内容管线

用户丢来一篇海外创作者/运营大 V 的方法论长文（Dan Koe 式的「一人公司」「创意团队」架构最典型），说「学习一下，有什么可以借鉴的」，或者直接说「把它整合进我们的 skill，然后落地」。这类任务的验收标准不是「总结这篇文章」，而是**管线里多了一条以后会一直走的规则 + 至少一个今天就能用的成品**。

## 第一步：拆解（先分清哪些是机制，哪些是广告）

这类文章恒定是三段拼装，必须物理分离，只吸收第一段：

1. **机制**（可迁移）：角色分离、选题树、签名文档、获客路径。判断标准=去掉他的工具和行业后是否仍然成立。
2. **自家工具推广**（不可迁移）：他的 SaaS、课程、Discord、模板包。一律不写进 skill，只在对话里点明是软广。
3. **他的行业特化例子**（半可迁移）：健身/电商/独立开发者案例只能当结构参照，不能当题材。

拆完立刻回答一个判断：**这套机制补的是我们管线的哪一段空缺**（多数情况是「选题树没有分叉方法」「起草前没有固定人设上下文」「没有 B 端获客动作」）。找不出空缺就不要整合——为整合而整合会让 skill 变胖且互相矛盾。

## 第二步：写进 skill 的哪一层

| 内容 | 落点 |
|------|------|
| 常驻规则（生成前必读什么、协作怎么分工、验收标准） | SKILL.md 正文，整段写 |
| 可以一次问到底的问卷/prompt 模板 | SKILL.md 里的 ```text 代码块，或 `references/` |
| 已填好的实例（本用户的思想签名、内容地图） | 不进 skill，进 Vault 的 SSOT 文件，skill 里只留路径 |
| 平台适配矩阵、切角决策表等按需查阅的深度 | `references/<topic>.md` |

**SSOT 文件放 Vault，不进 skill**：skill 会随仓库同步、会被其他会话读到，把个人品牌长文档塞进去会让 skill 体积失控且难以更新。skill 里只写「生成前先读 <绝对路径>」。

## 第三步：落地动作要成套，缺一项就等于没做

一次方法论整合至少交付这四件，否则用户下次还得重新催：

1. **SSOT 文档**：Obsidian `VAULT/05-Outputs/content-creator/` 下建 `<TOPIC>-SIGNATURE-<USER>.md`，同时镜像一份到个人 Superpowers 仓库 `docs/social-media/`（两处路径都写进 skill，Vault 是主，仓库是备份）。
2. **内容地图**：`ideas/content-map-YYYY-MM.md`，按「支柱 → 子话题 → 已核验选题 → 切角」四级铺开，每条选题挂一手硬数字——没有硬数字的选题不是选题，是感想。
3. **一个成品**：从地图里挑一条，当天写出完整草稿（长文/脚本都行），证明这套流程能出活。只交地图不交稿，用户无法判断这套方法行不行。
4. **接进在产管线**：把「生成前必读 SSOT」写进 `ai-tietu/cron-prompt.md` 与 `cron-prompt-longform.md` 的定位段——cron 才是每天真的在写东西的地方，只改 skill 不改 cron，方法论第二天就失效。

## 第四步：跨平台切角必须真的一鱼多吃

同一个选题要能同时喂长文和短视频，切角得按**读者的耐心长度**分，不是按话题分：

| 切角 | 时长/篇幅 | 开头承诺 | 落点 |
|------|-----------|----------|------|
| 硬数字短视频 | 60–85s | 一个反直觉数字 | 今天就能改的一个动作 |
| 小白降维 | 长文中段/次条 | 这个工程概念翻译成白领能做的防呆操作 | 5 步可复现 |
| 从业者深潜 | 长文头条 | 机制 + 单位经济学 | 我还没想清楚的地方 |
| 公开重构 | 图文/视频 | 某岗位糟糕的一天 | 重构前后账单对比 |

四个切角写在同一份地图里，排产时才不用临时想角度；每个切角必须自带不同的证据类型（数字 / 步骤 / 机制 / 成本），共用同一批证据等于没分角。

## 常见坑

- **只改 skill 不改 cron**：cron 里的 prompt 是独立文件，不引用 skill 正文。方法论写进 skill 而在产 cron 提示词没挂载 = 零效果。改完必须顺手 patch 两个 cron-prompt.md。
- **把作者的工具当机制写进流程**：他的编排器/工作台随时会关停收购，写进流程等于把管线绑在别人的产品生命周期上。
- **SSOT 写成营销文案**：「帮助 10 万+ 创作者实现增长」这类句子对生成毫无约束力。每一维必须能被检查——受众要有抱怨原话，反共识要能指名哪条流行建议是错的，专属词典要给出使用场景。
- **skill 里留旧仓库路径**：个人 Superpowers 仓库在 `~/Workspace/playground/HermesWork/marovole-Superpowers`，早期文档里写的 `~/Workspace/HermesWork/marovole-Superpowers` 已不存在。跨 skill 引用路径时以记忆中的现行路径为准，改完顺手检查同族 skill 是否还有旧路径。
- **选题树不带日期就当作常驻**：`content-map-YYYY-MM.md` 按月份命名，过期后仍可复用结构但要重核一遍硬数字——一年前的基准分数今天引用就是造谣。
