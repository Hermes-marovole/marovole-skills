## 一、编导判断单（No.00X · <一句话素材名>）

### 1. 为什么这条极爆

- **痛点反差**：全网现有做法 vs 我们的做法，用一句对照说清（谁在为什么付钱/踩什么坑）。
- **工程爽感**：一条可复现的技术链路，点名每个部件承担什么（谁管登录态、谁管纯净出口、谁管验证码）。
- **自然裂变钩子**：素材里是否自带邀请码 / 免费额度 / 可转发福利；有就放到文末，把流量换成可用的资源。

### 2. 独家实测干货点（3–5 条，别人没有的）

1. 具体命令 / 一行挂载方式（含 fallback）
2. 别人会踩死的坑 1 + 它为什么必然失败
3. 别人会踩死的坑 2 + 触发它的那个默认值
4. 跨端 / 跨工具的接力点（哪一步必须人上）
5. 彩蛋：被停用/404/403 的功能怎么绕（一句话说清机制，别写成流水账）

### 3. IP 对齐（个人号必填，规则见 topic-to-matrix/references/ip-principle.md）

- **真实案例出处**：X 原帖链接 / 评论原话 / 用户本人决策（不用同事举例），没有就写「无」，这条只能当判断类或资讯类做
- **卡在哪一步**：说清需求 / 拆成步骤 / 验收结果
- **并排实测**：随手问 vs 按三步法，测什么、记哪个数字
- **ip_fit 分 + 所属线**（方法演示 / FDE 现场 / 立场观点）
- **接回 slogan 的一句**：「不用学写代码，学会像产品经理一样指挥 AI」在这条里怎么落地

### 4. 思想签名落点

一句「这条素材暴露的工程审美是什么」，供 Brand Signature 对齐。

## 写法禁忌

- 不要在判断单里重述「我查了什么、读了哪几个文件」；用户只关心判断和可勾选项。
- 不要把选题做成开放问答题（「你想写哪个方向？」）。永远给已带标题方向的代号。
- 不要写「终版」「最终稿」；稿子一律按版本号命名。
- 数字、IP、报错原话必须来自本次真实会话，二手教程里的数字只能当背景，不能当证据。
- 不写「N 倍提效」这类无依据倍数；前 5 秒不出术语；不靠贬低某类人制造对立；vibe coding 不进主张句。
