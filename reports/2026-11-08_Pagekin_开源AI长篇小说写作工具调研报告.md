## 一、执行摘要

- **Pagekin（书童）是一款免费开源（GPL-3.0）的 AI 长篇小说写作桌面软件**，由独立开发者 EthanYoQ 维护，原名 AI-Novel-Writer，2026 年下半年更名。当前版本 v1.4.0（2026-10-29 发布），GitHub 2,429 stars、302 forks，技术栈为 Electron + TypeScript + React。
- **产品核心主张是"长篇一致性"**：围绕角色设定、世界观与章节蓝图管理上下文，AI 写每一章时拿到的是"本章蓝图 + 相关角色 + 世界观 + 前文摘要 + 上一章全文"，而非全书聊天记录。这一机制直接命中 AI 长篇创作最大的痛点——人物 OOC、设定遗忘、剧情断线。
- **商业模式与国内主流工具几乎完全错位**：软件免费开源、作品本地存储（SQLite）、模型不绑定（OpenAI 兼容协议 + Gemini 原生协议，支持 DeepSeek/OpenAI/xAI/Gemini/Ollama 等预设及自定义端点）。不收费、不代管模型额度、不提供在线社区。
- **竞品格局**：国内付费 SaaS（星月写作、蛙蛙写作、马良写作、笔灵等）主流路线是"会员/字数包 + 平台自带模型 + 云端存储"；海外（Sudowrite、NovelAI、Novelcrafter）则分"闭源订阅自带模型"与"BYOK 订阅"两派。**"开源 + 本地优先 + 模型中立"三者兼备的产品在国内外商业市场几乎空白**，Pagekin 与 SillyTavern、天命/天衍、Biz Novel Studio 等开源项目构成该路线的代表。
- **对本公司的启示**：Pagekin 的"结构化上下文管理 + 拆解仿写 + 审稿修稿闭环 + 写作 Skill 导入"工作流设计（尤其是把 SKILL.md 提示词技能绑定到生成环节的做法），对我们研发的营养学 AI 助手产品的"专业内容一致性管理"与"用户工作流定制"能力有直接的可借鉴价值。详见第八、九章。

### 3.2 产品定位

> "Pagekin，免费 AI 小说写作软件。从设定、架构、章节蓝图到正文、审稿、修稿、定稿，一章一章把书写完。本地优先：作品存在你自己的电脑上。软件不带模型：接你自己的 API Key，或用 Ollama 跑本地模型。"

三条核心卖点（官方明确表述）：

1. **结构化创作流程**：设定 → 架构（故事前提/角色名单/世界观/情节大纲）→ 章节蓝图 → 正文（写稿/审稿/修稿/定稿），每步产物存进作品，供下一步使用；
2. **本地优先**：作品文件夹 + 本地 SQLite，支持 WebDAV 云备份、Markdown/TXT 导出、版本历史回退；
3. **模型中立**：不附赠模型与额度，OpenAI 兼容 + Gemini 原生两套协议，预设 DeepSeek、SiliconFlow、智谱 BigModel、OpenAI、xAI、Gemini、Ollama、NovelAI（最小兼容），支持自定义端点。

另外三条官方"边界声明"（不承诺的事）也值得注意：不保证任意第三方 API 换 URL/Key 即接入；不替代作者创意与事实核查；不提供在线发布、阅读社区或云端模型账号。

### 3.3 功能架构详解

**（1）书房（作品管理）**
全部作品列表 + 封面概览（写作步骤、字数、定稿章数、角色数）；支持旧版项目导入副本。

**（2）拆解、仿写、续写与改写**
- 导入 .txt / .md / .epub 小说，拆章后可选用途：
  - **拆解与仿写**：AI 拆解结构、提取文风、反推章节蓝图，生成"仿写约束"供后续写作参考；参考书只进知识库，不混入正文；
  - **导入原稿续写**：自己的旧稿按章节号导入为定稿，AI 接着人物与情节续写（v1.4.0 起支持导入时反推设定/架构/角色和蓝图，只补空白不覆盖已有内容）；
- 段落级：选中正文可"续写 / 润色 / 扩写 / 改成对话 / 按意见改"（v1.4.0 新增按意见改写，要求最长 2000 字）；
- 整章改写走"修稿"：结果按段落 diff 呈现，作者逐段拍板。

**（3）设定与架构**
设定页：类型、受众、写作语言、总章数、每章字数。架构页四节：故事前提、角色名单、世界观、情节大纲，均可 AI 生成或手写，四节确认后才进入蓝图页。角色卡含基础设定、当前状态、关系图谱，可从文件导入。

**（4）章节蓝图**
逐章规划主角小目标、冲突与转折、悬念钩子、出场人物；AI 按章节范围分批生成、断点续作；单章写作选项小弹层选模型和作者指导；批量创作一次最多 10 章。

**（5）正文流水线（本章核心 SJ）**
单章视图内完成：AI 草稿 → 作者手编或 AI 审稿 → 审稿报告逐条勾选/忽略/自行追加意见 → 修稿按 diff 逐段确认 → 定稿。**定稿进入后续章节的连续性上下文。**

**（6）运行侧页（任务控制）**
所有生成任务集中在运行侧页：进行中/历史/诊断三页，实时流式预览、随时取消、批量可暂停；失败时已生成文字留作"恢复候选"，可复制或丢弃。

**（7）长篇辅助设施**
- 剧情与伏笔：主线/支线/伏笔按章节跟踪（在哪章埋设、推进、解决）；
- 知识库：导入参考资料（.txt/.md），配检索模型做语义检索，未配置时退化为本地全文检索；v1.4.0 起本地检索模型可不填 Key；
- 版本历史：每章历次稿件留存，可对比、可恢复为新草稿；定稿被回退替换后旧定稿保留为只读"已被替换的定稿"；
- 导出与备份：合并/分章 Markdown、TXT；本机打包 + 绑定 WebDAV 云备份，恢复总是另存副本。

**（8）写作 Skill（v1.3.x 起重点能力）**
设置页可从本机文件夹、单个 SKILL.md 或 GitHub 地址导入"提示词型写作技能"（例如"去 AI 味"、特定文风、特定题材写法），SKILL.md 引用的 references 一并装入；安装前展示内容待确认。装好后**绑定到规划/写稿/审稿/修稿某一阶段**，该阶段所有生成自动带上。仅支持自包含提示词，脚本、hook、子代理、工具调用不会被安装，技能无法执行代码。

**（9）其他**
浅色/深色主题、中/英双语界面、作品写作语言可选中文或英文；正文编辑器 Tab 起段首两空格、全键盘写完一章。

### 3.4 v1.4.0 版本要点（2026-10-29）

| 类别 | 内容 |
|---|---|
| 新功能 | 按意见改写选中文字（≤2000字，可恢复）、**分工模型**（规划/写稿/审稿/修稿/定稿后处理各环节可分别指定模型，未指定回落默认）、导入原稿反推设定（默认勾选、预显 AI 消耗、结果逐条采用）、回退定稿保留只读旧稿 |
| 改进 | 模型名合并输入候选列表、自动拉取端点模型列表、切换服务商清空旧 Key（防泄露）、连接测试超时缩短（云 30s / 本地 120s）、上下文超限改为提示建议而非硬拒发、导入按全书工作量定额 |
| 修复 | 备份往返、回退再定稿、蓝图重生的数据问题 |

**"分工模型"设计值得特别留意**：一个创作流水线内部按"环节"切换不同模型（如用便宜模型写审稿、强模型写正文），这在中长文本 Agent 产品设计中是明显优于"单一大模型打天下"的成本/质量权衡。

## 四、长篇一致性机制对比（本报告核心）

第五章竞品横向比较前，先把"各家如何对抗人物 OOC / 设定遗忘 / 剧情断线"单拎出来——这是长篇小说工具真正的技术分水岭。

### 4.1 Pagekin 的机制

- **上下文带宽**：写第 N 章时，AI 输入 = 本章蓝图 + 相关角色卡 + 世界观 + 前文摘要 + 上一章全文。**"摘要层（全书）+ 全文层（上一章）+ 设定层（实体卡）"三层合一**；
- **实体承载**：角色卡带"当前位置状态"（定稿后处理自动写入并刷新），蓝图有全章结构；
- **检索**：知识库可选启用向量检索（LanceDB + 检索模型），未配置退化为全文检索；
- **校验**：内置 AI 审稿（其意见逐条可勾选进修稿）、伏笔/剧情树自动识别、修稿 diff 逐段人工确认——**"生成后审计 + 人工终审"而不是纯自动校验**。

### 4.2 五种流派横向盘点（综合两份竞品底稿结论）

| 流派 | 代表产品 | 机制概括 | 优势 | 弱点 |
|---|---|---|---|---|
| ① 实体卡 + 全量带入 | Sudowrite Story Bible | 每次生成都全量携带结构化 Bible + 约2万词正文窗口 | 心智负担最低，文风对齐好 | token 成本高；无公开检索证据 |
| ② 关键词触发 + 预算 | NovelAI Lorebook、Novelcrafter Codex、SillyTavern World Info | mention/keyword 决定注入，token 预算控总量，插入序定优先级 | 精准、可控、生态标准词汇 | 漏触发即盲区（激活≠对齐）；配置门槛高 |
| ③ 关键词 + 语义双通道 | SillyTavern Vector Storage、Smart Connections、Biz Novel Studio、novel-studio | embedding 召回兜底 keyword 漏触发 | 减少漏报 | 长篇正文 OOC 仍是主要盲区 |
| ④ 事实层状态回写 | 天命/天衍（15维事实快照+生成门禁）、novel-harness、NovelGenerator | 不依赖模型记忆/检索，每章生成后回写结构化事实并用其校验第 N+1 章 | 超长篇（3000章级）验证有效；token 最省 | 回写流程重、工程门槛高 |
| ⑤ 主动无 AI | Plottr、Inkswell（非AI模式）、Atticus | 人工维护结构化模板 | 隐私友好、无 token 成本 | 效率上限低 |

### 4.3 Pagekin 在坐标系中的位置

Pagekin ≈ 流派②（mention 检测式的实体卡注入）+ 流派①的"上一章全文常驻" + 流派④的"定稿即写状态"（角色状态由定稿后处理自动更新）+ 流派③的可选向量检索。**没有走纯 Agent/工具调用路线**（对比 Biz Novel Studio 的"自动导演" LangGraph Agent），也不做"一键生成百万字"式卖法——它的哲学是"AI 起草、每步人确认"，与国内星月写作式的"一键完成"路线形成光谱两端。

### 4.4 各家上下文注入机制细化

| 工具 | 实体承载形式 | 注入策略 | 摘要/记忆层 | 检索方式 | 一致性校验 |
|---|---|---|---|---|---|
| Pagekin | 角色卡（含状态/关系）+ 章节蓝图 | 每章生成携带蓝图+相关角色+世界观+前文摘要+上一章全文 | 前文摘要 | LanceDB 向量（可选）/全文检索 | AI 审稿报告 + 伏笔树 + 修稿 diff 人工确认 |
| Sudowrite | Story Bible 分层（Braindump→Synopsis→Character 卡→Worldbuilding→Beat） | 每次生成全量携带 + 约2万词正文窗口 | 无（靠窗口与 Chapter Continuity 跨最多25文档） | 无向量证据 | 无显式校验 |
| NovelAI | Lorebook 词条（key 触发、token 预算、插入序、级联） | keyword 触发 + 递归 + 级联 | Memory（顶端常驻）+ Author's Note（近端） | 无向量证据 | Context Viewer 手工审计（透明化组装） |
| Novelcrafter | Codex wiki 实体 + 关系图 + Progressions（随时间变更设定） | 三档 tracking（always/detected/never）+ mention 检测 + POV + 关系级联 | AI Scene Summarization | 无向量证据 | Advanced Review（官方标 planned） |
| SillyTavern | World Info + Character Card V2/V3 | keyword 触发（默认25%预算、scan depth、递归、插入深度）+ Vector Storage 语义候补 | 社区记忆扩展 | keyword + embedding 双通道 | 无显式校验 |
| 马良写作 | 人物档案 + 伏笔 + 时间线（档案员 Agent 按正文更新） | 智能上下文窗口管理 + 对话式前情接续 | 档案自动联动 | 未公开（待核实） | 独立审稿 Agent |
| 蛙蛙写作 | 总纲/卷纲/章纲/人物/世界观结构化字段 | 约 30+ 作品数据字段自动拉取；Weaver 自研模型动态长短期记忆（伏笔存长期记忆） | 内置于模型侧 | 内置 | 未公开 |

| 社区娱乐型 | 彩云小梦 | 续写分支树 + 角色扮演广场社区；世界设定（词条/人物/关系）结构化；单作品上限约 10 万字；会员 25 元/月起（iOS 口径）；闭源云端 + 自研模型，不开放 API |
| SaaS 网赚型 | 笔灵 AI、星月写作、墨狐 AI、灵犀速写 | 会员/字数包计费（星月 9.9 元/10万字起、包月 79 元起、至尊包年 1799 元；笔灵主站终身 VIP 199 元），靠爆款模板、"月入过万"变现叙事增长；多数闭源自带模型，仅灵犀支持自定义 API |
| 专业深度型 | 蛙蛙写作、马良写作、FeelFish | "设定档案 + 多级大纲 + 上下文管理"三件套，是 Pagekin 的直接对标组（5.3 节细说） |

### 5.2 国内商业产品的两个显著倾向

1. **"变现叙事"主导产品形态**：星月写作最典型——扫榜（番茄各细分榜风向）→ AI 拆书 → 大纲/细纲/黄金开篇 → 文 → 润色去 AI 味 → 投稿，工具只是"教人用 AI 写网文月入过万"课程的漏斗入口，社群 + 付费课程（88 元速成营、99+押金打卡营）二次变现；2024-06 上线一年获 2 万+ 月活、团队 8 人月入百万、付费率超 17%（36氪/极客公园口径）。
2. **平台监管急转直下**：番茄小说 2026-05 治理公告披露已拒签低质书籍 11.27 万本，星月写作宣传的多部百万级在读案例被批量下架（封禁理由"存在 AI 低质表达"）；2026-10 新签约规则把 Lv.0/Lv.1 作者压到"完本签约"；起点要求 AI 辅助需 ≥30% 人工深度修改并主动申报，晋江只允许校对级/元素级/梗概级三种 AI 用法。**"一键生成去投稿"路径在国内已基本走死，"AI 起草 + 作者深度参与"是唯一合规方向——而这恰是 Pagekin 的产品哲学。**

### 5.3 直接对标组细评

| 产品 | 与 Pagekin 其他 | 关键差异 |
|---|---|---|
| **蛙蛙写作** | 同有"设定 + 三级大纲 + 正文"三件套 | 云端 SaaS + 自研 Weaver 模型（2024-10 并入 OPPO，模型栈开放情况待核实）+ 蛙币/会员计费；承诺不用作品训练 AI |
| **马良写作** | 国内最接近 Pagekin 精神的产品：多智能体（主助手/写手/档案员/审稿员分工）+ 按任务分模型 + 用户自有 API | SaaS 订阅 + 积分制为主流形态；另有开源可私有化部署版（Deng-m1/MaliangAINovalWriter，企业级积分账本/按模型计费审计）；"作者拍板、AI 分工"理念与 Pagekin 同向 |
| **FeelFish** | 形态最像（桌面客户端 + 多模型接入 + 设定文档 + 长篇上下文管理，Windows/macOS/鸿蒙） | 闭源 + 积分制收费（积分≈Token 支出，官方口径一亿积分约写 10 万字）；"数据本地"表述含糊待核实 |

**结论（直接竞品分析）**：在国内商业市场，**"GPL 开源 + 本地 SQLite + 模型不绑定"五件套几乎无竞品同时满足**；马良是精神近亲但主业是 SaaS；FeelFish 是形态影子但是闭源收费。Pagekin 在国内没有严格意义的敌人，而它可能进入的是"开源折腾圈"与"专业网文作者"两个受众的中间地带。

## 八、机会与威胁分析

### 8.1 Pagekin 的机会

1. **空白区卡位**：国内外商业产品均未同时提供"开源 + 本地数据 + 模型不绑定 + 免费"四件套；隐私敏感用户、预算敏感作者、模型自主权爱好者的需求是真实存在的（开源圈天命、InkOS、Biz Novel Studio 的活跃佐证）；
2. **合规红利**：国内平台对"一键生成"收紧审核（番茄 2026-05/10 连续治理、起点/晋江 30% 人工比率规则），"AI 起草 + 人工确认每步"是我们的哲学，恰好符合监管方向；
3. **结构护城河**：写作 Skill 生态（SKILL.md 提示词即技能）+ 分工模型 + 拆解仿写约束，构成可扩展但轻量的能力体系；
4. **独立开发者口碑周期**：4 个月 2400+ stars 且保持双周级发版，社区动力健康。

### 8.2 Pagekin 的威胁与弱点

1. **签名/公证缺失**：企业或多人协作场景部署阻力；对"下载来源安全性"要求高的普通用户有劝退效应；
2. **无协作/无同步**：不提供在线发布（阅读/阅读社区），协作写作是用户需求（Novelcrafter Specialist $20 档主打协作），本地优先路线天然要做专项设计（WebDAV 只解决了单作者备份）；
3. **商业天花板**：纯开源 + 免费，若长期维持，功能演进速度将受制于个人精力（助手聊天入口因 1.3.0 重构而临时隐藏，即是个人维护带宽的信号）；
4. **Agent 化滞后**：相对 Biz Novel Studio（LangGraph 自动导演）与马良（多智能体分工），Pagekin 刻意不做自动 Agent 流水线；这保住了"作者拍板"哲学，但对部分重度用户而言"批量 10 章"已是其自动化上限；
5. **模型生态变数**：OpenAI 兼容协议覆盖面大但官方明确"不保证任意第三方 API 换 URL/Key 即接入"；Anthropic 原生、KoboldAI 等需要单独适配器，目前未支持。

### 8.3 对我们（合成生物学/营养保健品公司 AI 产品线）的启示

本次调研的原始动机是"看到一条推、去把这条线摸透"，但把 Pagekin 的设计决策摆到我们正在开发的 AI 产品（面向 C 端的健康助手小程序/App、面向 B 端营养师的营养学助手 WebApp）旁边，有多处值得借鉴：

1. **专业领域的"一致性管理"是同一个问题的另一种表述**：Pagekin 默认"角色不可 OOC、设定不可遗忘"，营养学助手对应的应是"剂量/相互作用/适应症数据不可漂移、引用文献不可幻觉"。Pagekin 的"蓝图（本章目标）+ 实体卡（角色）+ 前文摘要（全书）+ 上一章全文（近因）"上下文组装法，可以平移为"任务目标 + 知识实体卡（营养素/用户档案/指南条目）+ 长程上下文摘要 + 最近会话原文"；
2. **"审稿报告逐条勾选 → diff 修稿 → 每步人工拍板"的交互范式很适合 B 端专业助手**：营养师不会信任一键生成的营养方案，但会接受"AI 给出可逐条采纳/忽略的审校意见 + 修改前后对比"的系统——这比黑盒生成建立的信任链强得多；
3. **写作 Skill = 可插拔的领域技术知识**：Pagekin 允许把"去 AI 味"等提示词技能绑定到特定生成阶段，这同样可以用于把"中国的 DRIs 表述习惯""FDA 合规话术"等领域提示词包做成可插拔资产——**且与 Hermes Agent 的 SKILL.md 机制同构**，我们已有的技能库资产理论上可以低成本复用；
4. **分工模型（按环节指派不同模型）**：审稿用便宜模型、正文用强模型的做法，在我们 3 条产品线上都是直接可复制的成本优化；
5. **本地优先不仅是隐私主张，也是默认信任**：Pagekin 把"本地保存"与"本地生成"区分开的隐私表述方式，值得我们所有产品文案借鉴——数据在哪、什么条件下会离开设备，都要拆开说清楚；
6. **风险预警**：Pagekin 的 GPL-3.0 许可证意味着**其代码不可直接闭源吸收进我们的商业 App**（Linux/GNU 传染性），学习和借鉴必须停留在产品/交互/机制层面，不能拷贝代码。若确有吸收代码的需要，须以独立开源合规审查为前提。

## 九、结论与建议

### 9.1 结论

1. Pagekin 是当前**开源侧产品完成度最高的"结构化长篇小说写作工作台"之一**，其价值在产品机制设计（上下文组装、审修闭环、技能注入）权重远高于模型能力本身；
2. 长篇一致性问题已被行业收敛为五种流派，Pagekin 走的是"结构化实体注入 + 人工终审"路线，配合 LanceDB 本地向量库，其 token 成本与可控性占优；
3. 国内付费 SaaS 工具正遭遇平台治理硬着陆（番茄大规模下架、签约规则收紧），"AI 起草 + 人工确认"路线因此获得合规红利；
4. 该赛道与本公司 AI 产品（营养助手）共享"专业领域一致性管理"与"可插拔领域技能"两个基础机制，但 GPL-3.0 禁止代码级复用。

### 9.2 建议的下一步

| 建议 | 优先级 | 说明 |
|---|---|---|
| ① 对 Pagekin 做一次 30 分钟真机试用（macOS arm64 DMG v1.4.0），验证审稿修稿闭环与拆解仿写约束的真实体验 | 中 | 确认是否值得作为"营养学助手 WebApp 审稿交互"的参照原型 | 
| ② 立项评估：把"审稿意见逐条勾选 + diff 逐段确认"写入营养学助手 WebApp 的需求清单 | 中 | 可直接引用本报告第四章机制对比作为立项依据 |
| ③ 建立"提示词技能包"规范：参照 Pagekin 的 SKILL.md 引用结构（自包含提示词 + references/），沉淀公司领域技能（DRIs 表述、FDA 合规话术等） | 高 | 与 Hermes Agent 技能体系同构，边际成本低 |
| ④ 关注 Pagekin（GitHub Releases）与马良开源版（MaliangAINovalWriter）两条线的产品演进 | 低 | 每季度复盘一次即可 |
