## 二、PM 指挥 AI 三步法 · 可复制指令模板

### 第一步：说清需求（用真实提问与竞品漏斗定靶子）

**模板 A · GSC 16 个月长尾问题清洗指令**
> 导出 Google Search Console 最近 16 个月查询表（先在 GSC 用正则 `^(?:\S+\s+){7,}\S+$` 或包含 `how|what|why` 筛出自然语言提问，再导出 CSV 附在本地目录）。

```text
请读取本地导出的 GSC 查询 CSV（最近 16 个月数据），只做筛选与诊断，不要编造表外数据：
1. 筛出「高展示、低点击率」的 8 词以上提问，按展示量降序列出前 15 条，并标出当前对应着陆页 URL；
2. 单独筛出当前平均排名落在第 8–15 位的页面清单，按展示量排序；
3. 针对前 5 个高展示低点击问题，对照对应页面的首段原文，指出「用户问了什么 vs 页面前 100 字到底有没有直接回答」，并给出一版不超过 80 字的首段直答改写草稿。
输出格式：Markdown 表格 + 逐页修改建议，每条必须附 CSV 原行数据。
```

**模板 B · 竞品公开信号与 AI 引用源摸底指令**
```text
针对我们的核心品类问题：「[填入 3–5 个真实买家会问的问题，例如：What is the best tool for ...?]」：
1. 先汇总我们在 ChatGPT / Google AI 概览里实际记录到的推荐品牌与被引用页面 URL（只使用我提供的截图或抓取文本，不要凭记忆补链接）；
2. 将被引用页面按类型分类：产品官网 / 第三方评测榜单 / Reddit 社区讨论 / 文档或百科，并统计官网占比 vs 第三方占比；
3. 针对排名前 3 的竞争页面，拆解它们的内容形态（清单对比 / 免费工具 / 实操指南）和核心信息块，输出一份「我们需要补齐的页面清单 + 需要争取客观收录的第三方榜单清单」。
```

### 第二步：拆成步骤（搭 AI 读得懂的基础设施 + 真材实料内容）

**模板 C · 站点 AI 爬虫与可读性技术体检清单（直接交给 Coding Agent 跑）**
```text
请检查站点 [https://your-domain.com] 的 AI 可读性，逐项运行真实请求并附上原始返回，不要猜测：
1. 检查 /robots.txt：分别核对 OAI-SearchBot（ChatGPT 搜索收录）、GPTBot（OpenAI 模型训练）、Googlebot 是否被误屏蔽；明确分开报告「搜索收录权限」与「训练语料权限」；
2. 模拟无 JS 执行环境（纯 curl 抓 HTML）检查首页、About 页与 3 篇核心产品页：核心标题、产品定义、定价与关键段落是否直接出现在初始 HTML 中，而非依赖客户端 JS 渲染后才出现；
3. 检查 About 页：能否在 3 句话内用大白话讲清「你是谁、做什么、给谁用、不给谁用」；
4. （可选）参考 platform.claude.com/llms.txt 的精简结构，起草一份不超过 60 行的根目录 /llms.txt 草案（只列核心产品定位、文档与关键页链接），并在备注里注明「仅供 AI Agent 理解站点结构，不计入 Google 搜索排名预期」。
```

**模板 D · 30 分钟创始人访谈转写 → 高信噪比干货文章指令（借用 Slide 04 #02，落到自有官网）**
```text
以下是我围绕「[具体客户痛点]」做的 30 分钟语音访谈逐字稿：[粘贴或附文件路径]。
请按产品经理写说明文档的标准整理成一篇发在我们自己官网的深度解答，严格遵守：
1. 第一段前 3 句话直接给出核心结论与适用边界，不写空泛行业背景；
2. 只提取访谈稿里出现过的真实案例、数字、取舍条件与踩坑细节，禁止补充稿件外的数据或夸张倍数；
3. 凡是访谈稿里没讲清、需要补查证据的地方，用 [待补查：...] 标出来，不要自己脑补；
4. 文末附 3 条站内相关页面的内链建议（发稿当天同步挂上）。
```

### 第三步：建验收台（把 SEO / GEO 从一次性清单改成每周对账表）

**模板 E · 每周 15 分钟 SEO & GEO 验收台账**
```text
请对照上周与本周的记录，生成本周验收简报（没有数据的格子填「未采集」，禁止推算）：
1. 索引检查：本周新发布的页面 URL，是否均已在 GSC 执行 URL Inspection 并确认收录状态；
2. 下滑预警：本周排名下滑超过 3 位、或点击明显下降的重点页面清单，给出 1 条具体更新动作（补首段直答 / 更新过时数据 / 补站内链接）；
3. AI 引用对账：针对固定的 5 个核心品类问题，记录本周 AI 回答点名的品牌与实际引用页面 URL，对照上周看新增或消失了哪些引用源；
4. 红线自查：本周准备发布的外部投稿或社区回复，是否全部做到「有真实使用信息、不隐藏作者身份、不为了蹭权重批量铺重复页面」。
```
