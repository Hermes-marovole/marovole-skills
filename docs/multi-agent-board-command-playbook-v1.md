# 多 Agent 公告板协作：PM 指挥 AI 落地工作流模板 v1

> **整理归属**：来自翡冷翠  
> **版本**：v1（2026-11-26）  
> **定位**：提炼自 Google Antigravity `/swarm` 官方机制与开源项目 `ythx-101/herd-skill` 的纯文本编排协议，剥离对特定 CLI 或多台 VPS 的硬依赖，改写成产品经理与非技术团队也能直接照搬的「说清需求 → 拆成步骤 → 建验收台」三步指挥模板。  
> **源帖与代码核查存档**：`docs/x2doc-herd-skill-vs-antigravity-swarm-2026-11-26.md`

---

## 一、先选路：单机内置编排 vs 跨工具纯文本协议

| 判断维度 | 直接用单产品内置（如 Antigravity `/swarm`） | 借用纯文本协议 + 轻量巡检（如 `herd-skill` 思路） |
| --- | --- | --- |
| **适用前提** | 单机、同生态模型选择器内够用、任务可按文件干净拆分 | 要混用多家 CLI/模型、跨多台机器跑、或想把验收绑死在命令与截止时间上 |
| **开箱省心度** | 一条命令起步，自带看板、工作副本隔离、原地换模型 | 需准备运行环境（`herdr` TUI 0.9.5、SSH 密钥、`flock`）与任务书/花名册 |
| **核心风险** | 同额度池容易集体撞限暂停，额度刷新后不会自动恢复 | 无工作区沙盒、无花费上限，文件越界靠任务书约定兜底 |

## 二、第一步：说清需求（≤60 行任务书 + 成员花名册）

> 借鉴 `herd-skill` 的铁律：一份任务书不超过 60 行，把「谁干什么、不能碰什么、几点交卷、用哪条命令验货、额度用完换谁」一次性写死在纯文本里。

### 模板 A · 60 行上限多 Agent 任务书（`BRIEF.md`）

```markdown
# <项目名> 任务书（BRIEF）

- 你的角色：<成员名>（运行环境：<本机 / 机器标签>，主模型：<模型 A>）
- 硬截止时间：<YYYY-MM-DD HH:MM CST>（<HH:MM UTC>）。到点按现有产物验收收卷，不延期；宁可范围收敛而稳，不交半成品。
- 工作目录：<绝对路径>

## 边界铁律（必守）
1. 只修改你负责的文件：<列出明确路径>。严禁改动其他成员负责的文件与项目外文件。
2. 遇到依赖缺失、权限拦截或同一报错卡住超过 10 分钟，立刻发帖 @coordinator 说明卡点，不要空转重试。
3. 严禁虚构数字、日期、链接或未执行的检查结果。

## 交付清单与机器验收命令（以命令退出码 0 为准）
- [ ] 产物 1：<文件路径>｜验收命令：`<例如：pytest tests/foo.py 或 python3 check.py out.json>`
- [ ] 产物 2：<文件路径>｜验收命令：`<例如：格式/字数/链接校验命令>`
- [ ] 交接报告：`<成员名>_REPORT.md`（只写三栏：改了什么、跑了哪条验收命令及原样输出、已知未解决项）

## 备用模型与故障口径
- 遇真实额度耗尽（如 quota reached / RESOURCE_EXHAUSTED）：立即 @coordinator 切换备用模型 <模型 B>。
- 遇临时过载（如 503 No capacity）：不等同于额度耗尽，等待 1 分钟后重试。

## 公告板约定
- 所有交接与提问发在共享公告板，引用前文写 `#序号`，不要重复贴长文。
- 完工必须发：`@coordinator [done] <一句话结论 + 报告路径>`。停笔（idle）不算完工。
```

## 三、第二步：拆成步骤（开工前探活 + 机械巡检代替模型盯梢）

### 模板 B · 开工前 2 分钟探活清单（Preflight）

在派发多路并行任务前，对每个准备上场的模型或账号先跑一次极短探活（返回单个固定词如 `pong`），按四档归类再派活：

1. **`ok`**：正常响应该词，进入主力名单，同时为每个席位预留 1 个备用模型。
2. **`quota`**：命中额度耗尽明确短语，直接换备用模型，不带病开工。
3. **`no-capacity`**：命中 `503` / 暂无容量，记为临时拥堵，稍后重试，不必误判成额度归零。
4. **`timeout` / `error`**：网络、权限或配置异常，修通再启动并行，避免多路一起报错空烧额度。

### 模板 C · 确定性巡检与停滞/截止提醒规则

不要让昂贵的大模型每隔几分钟「自己刷屏看进度」。把四件事交给脚本或固定节奏的轻量巡检：
- **唤醒门铃**：只在公告板出现新帖且命中 `@名字` / `@组` / `@all` 时，发一行带 `#序号` 的短提醒。
- **阻塞退避**：目标成员处于等待人工确认（blocked）时跳过提醒、不推进已读游标，待解除阻塞后再补发，避免消息吞掉。
- **停滞预警**：超过设定静默分钟数（如 10–15 分钟）无新帖且仍有成员未发 `[done]`，向协调者告警点名未交卷成员。
- **硬截止闹钟**：到达绝对截止时间触发一次收卷提醒，立刻按现有产物结算。

## 四、第三步：建验收台（双条件门禁 + 零上下文盲审）

### 模板 D · 协调者验收与匿名盲审指令

```text
你是独立盲审验收员（本次未读取讨论过程，只看最终产物与评分标准）。
请只读取以下已匿名化的产物文件与验收规则，不要猜测作者或过程：
- 待审产物：A = <路径1>，B = <路径2>（单方案则只审 A）
- 需求与硬门槛：<BRIEF 路径>

请逐项执行并输出 Markdown 表格：
1. 先核对 BRIEF 中每一条机器验收命令的真实退出码与输出（未实跑标「未验证」，禁止口头放行）；
2. 逐条对照 BRIEF 里的边界铁律，检查是否存在越界改文件、漏项、编造数字或未说明的假设；
3. 按【通过 / 需返工（给最小改动项）/ 退回】给出判定，并将结果写入 <review_path>，完成后仅发一条 `@coordinator [done] <review_path>`。
```

### 协调者收卷 3 条硬原则
1. **停笔 ≠ 完工**：任何工具显示的 `idle` / `done` 仅代表进程停止输出；必须同时满足「公告板 `[done]` 帖 + 协调者亲自复跑检查命令通过」。
2. **高风险产物换模型盲审**：用与写稿/写代码不同的模型做零上下文验收，不把草稿讨论记录喂给验收员，防止互相迁就。
3. **到点硬截断**：超过截止时间不再无限加时，按已通过机检的产物收卷，并在项目目录留一份 5 行复盘（结果、耗时、踩过的坑）。
